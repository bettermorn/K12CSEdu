# 一、使用说明与教学理念

## 1.1 一条主线

计算思维 = 分解 + 模式识别 + 抽象 + 算法设计。CSTA 材料指出，**模式识别在 CSTA 中归属"抽象"实践（CT7a）**，目的是"从具体到通用"。教学时要让学生体会：先拆开，再找共同点，再提取通用模型，最后写出步骤并检验。每个课时结束前请让学生用"四要素自查卡"回顾一次。

## 1.2 教师的角色

- **提问者，不是讲解者**：多问"为什么这样拆""哪里一样""如果换成……""怎么证明对"。
- **示范思维过程**：解题时大声说出想法，包括走错路再退回来的过程。
- **容许多种答案**：问卷第八部分要求"允许多种合理答案"，尤其是开放题，关注是否分解合理、逻辑清楚、可执行、有反馈。
- **重过程不只看结果**：数列题答对不代表理解了规律，要看他的解释过程。

## 1.3 边界提醒（避免教得过深）

依据 CSTA 边界说明，下列内容**不作要求**：
- 不要求 Big-O 复杂度分析（用实测比较即可）；
- 不要求实现链表、栈、树等数据结构（只要求为场景选型并说明理由）；
- 机器学习只要求会训练、会测试评估、会解释选择理由，不要求推导算法。

教有余力的学生可以拓展，但**评分上限**以上述边界为准。

## 1.4 课堂基本流程（每课时 45 分钟）【设计】

| 时间 | 环节 | 要点 |
|---|---|---|
| 0–5 | 情境导入 | 用一个真实小问题引起思考，先不给答案 |
| 5–15 | 概念与例题 | 概念卡 + 例题思路，教师示范思维过程 |
| 15–35 | 学生任务 | ★基础任务全员完成；★★、★★★分层选做；教师巡视 |
| 35–42 | 分享与追问 | 抽 2–3 名学生展示，追问"为什么""还有别的办法吗" |
| 42–45 | 四要素自查 + 微训练布置 | 学生填四要素自查卡 |

# 二、四要素教学要点与常见误区

## 2.1 分解问题

| 项目 | 内容 |
|---|---|
| **核心理念** | 复杂问题可以拆成更小、更清楚、可以单独处理的部分 |
| **CSTA 对应** | CT6c；高中核心：HS-PRO-PD-12（模块化）、HS-PRO-PD-15（协作）、HS-SYS-NT-34/35、HS-SYS-SE-32 |
| **教学关键句** | "这件事能拆成哪几块？""哪一块可以先做？""块和块之间靠什么连接？" |
| **课堂示范** | 用"早晨准备上学"为例：洗漱、吃饭、整理书包可以并行（部分），出门必须在这些之后 |
| **常见误区** | ① 只把任务逐条罗列，不归类（问卷强调"不会把所有任务简单堆在一起"）；② 拆得过细或过粗；③ 只拆不画关系；④ 忽略并行 |
| **追问策略** | "你为什么把这两件事放在一起？""删掉这一块会影响哪一块？" |
| **达标信号** | 能独立画出任务依赖图；能指出可并行和必须顺序的部分；能用流程图、任务清单或模块图表示问题结构 |

## 2.2 模式识别

| 项目 | 内容 |
|---|---|
| **核心理念** | 发现重复、规律与共性，并把规律推广到类似问题 |
| **CSTA 对应** | CT7a；高中核心：HS-ALG-PS-02、HS-DAT-DC-23、HS-DAT-DI-25/26、HS-ALG-ML-08、HS-ALG-IM-10 |
| **教学关键句** | "这和我们以前做过的哪一题像？""哪些地方每次都一样？哪些地方变了？" |
| **CSTA 的区分** | 人识别模式（数据分析、代码重构）与机器识别模式（机器学习）。高二以人为主，高三引入机器 |
| **常见误区** | ① 只会背答案，不能说规律；② 把巧合当规律（样本太少）；③ 把相关当因果；④ 只看单题，看不到"这是一类问题"（问卷自评中的反向表述）；⑤ 过度套用，忽略差异 |
| **追问策略** | "再给一个数据，你的规律还成立吗？""有没有反例？" |
| **达标信号** | 能说出规律并用公式或规则表达；能迁移到新问题；能识别重复操作并用循环表达 |

## 2.3 抽象

| 项目 | 内容 |
|---|---|
| **核心理念** | 抓住本质、忽略无关，用符号、变量、表格、状态或模型表示现实 |
| **CSTA 对应** | CT7a、CT7b、CT7c；高中核心：HS-ALG-PS-01、HS-PRO-VD-16、HS-PRO-RD-17、HS-DAT-DC-21/22 |
| **教学关键句** | "为了完成这个目标，哪些信息是必须的？""如果删掉这个信息，会出问题吗？" |
| **课堂示范** | 地铁线路图：忽略真实距离与弯曲，只保留站点与连接关系 |
| **常见误区** | ① 什么都想收集（缺少"为目标服务"的标准）；② 删掉必要信息；③ 把抽象理解为"画得简单"；④ 忽略隐私（问卷要求"信息最小化"）；⑤ 不理解"同一个对象可以有不同表示方式" |
| **追问策略** | "换一个目标，你的选择会变吗？""你忽略的东西有可能影响结果吗？" |
| **达标信号** | 能说明保留什么、忽略什么及理由；能把现实问题转成输入—处理—输出；理解编码与解码 |

## 2.4 算法设计

| 项目 | 内容 |
|---|---|
| **核心理念** | 用明确、合理、可执行的步骤解决问题，并检验、改进 |
| **CSTA 对应** | CT8、CT9；高中核心：HS-ALG-PS-01/02/03/04、HS-ALG-ML-06、HS-PRO-RD-18、HS-PRO-TR-19/20 |
| **教学关键句** | "按你的步骤，另一个人能不能做出同样的结果？""最容易出错的输入是什么？" |
| **常见误区** | ① 步骤含糊（"进行排序""处理数据"）；② 想一步做一步，没有整体顺序（问卷反向题所描述的行为）；③ 只测一个例子就认为对；④ 忘记边界（空、一个、临界）；⑤ 信任 AI 或同学代码而不检验；⑥ 步骤有遗漏、重复或死循环 |
| **追问策略** | "你自己演算一遍给我看。""如果输入是空的呢？恰好等于 60 呢？" |
| **达标信号** | 步骤完整、顺序合理；能用条件、循环；能选择合适的方法；能检查遗漏、死循环、重复 |

# 三、评价体系

## 3.1 评价原则

1. **自评 + 情境任务 + 过程记录**三者结合；
2. **先诊断后教学**，前测用于分层，后测用于看增量（问卷第八部分建议"可进行前测和后测"）；
3. **不把问卷作为唯一评价依据**（问卷首页声明用于学习与教学诊断，不作为学生能力或成绩的唯一依据）；
4. **按边界评分**，不超过 CSTA 对本年级的要求。

## 3.2 评测问卷使用流程

| 步骤 | 内容 |
|---|---|
| 1 准备 | 打印问卷；准备草稿纸；**不允许使用网络搜索**（除特别说明）；时间 30–40 分钟 |
| 2 说明 | 向学生说明"第一部分没有对错""第二部分是自评""第三部分起需要认真作答""结果不计入学期成绩" |
| 3 实施 | 巡视但不提示；允许学生用草稿纸；不许讨论 |
| 4 评分 | 先评自评（见 3.3），再评能力测试（见 3.4 与第五部分），共 85 分 |
| 5 分析 | 做维度剖面图，识别最弱要素；对照自评与实测（见 3.6） |
| 6 反馈 | 向学生反馈优势与改进建议，不公布排名 |

## 3.3 自评量表评分【问卷】

- 共 20 题，4 个维度各 5 题，1–5 分；
- **第 4、9、14、19 题为反向题**：5→1，4→2，3→3，2→4，1→5；
- 每个维度满分 25 分：

| 分数 | 含义 |
|---|---|
| 21–25 | 自我感知较强 |
| 16–20 | 自我感知中等 |
| 5–15 | 需要进一步培养 |

## 3.4 能力测试评分【问卷】

| 部分 | 题号 | 分值 |
|---|---|---|
| 分解问题 | 第 1–3 题 | 8 + 6 + 6 = 20 |
| 模式识别 | 第 4–6 题 | 4 + 5 + 4 = 13 |
| 抽象 | 第 7–9 题 | 6 + 5 + 5 = 16 |
| 算法设计 | 第 10–12 题 | 4 + 6 + 6 = 16 |
| 综合开放题 | 第 13 题 | 12 |
| 人工智能问题 | 第 14 题 | 8 |
| **总分** | | **85** |

> 各题分值由问卷各题评分标准汇总，六部分合计 20+13+16+16+12+8 = 85 分，与问卷总分一致。

**折算百分制**：最终得分 = 实际得分 ÷ 85 × 100。

| 百分制得分 | 水平 | 主要表现 |
|---|---|---|
| 85–100 | 较强 | 能独立分析复杂问题，发现规律，建立模型并设计清晰算法 |
| 70–84 | 良好 | 基本掌握计算思维方法，能够解决常见问题 |
| 60–69 | 中等 | 有一定意识，但在抽象、流程设计或规律迁移方面不够稳定 |
| 60 以下 | 需要加强 | 容易混淆任务关系，难以提取规律或形成完整解决步骤 |

## 3.5 与年级目标的对应【设计】

| 年级 | 后测目标（班级平均） | 说明 |
|---|---|---|
| 高一 | 较前测提高；达到"中等"以上占多数 | 重点看增量，不要和高三比 |
| 高二 | 达到"良好"以上 | 对应 CSTA HS 基础标准 |
| 高三 | "良好"占多数，部分达到"较强" | 对应向 S1 进阶 |

## 3.6 自评与实测的对照解读【设计，依据问卷第八部分"不要只看自评得分"】

| 情形 | 判断 | 建议 |
|---|---|---|
| 自评高，实测高 | 自我认知准确 | 提供挑战任务 |
| 自评高，实测低 | 可能高估（"我觉得我会"） | 用测试用例、反例、同伴评审让其发现差距 |
| 自评低，实测高 | 可能低估，缺乏信心 | 用成功案例反馈，肯定具体做法 |
| 自评低，实测低 | 基础薄弱 | 加强不插电活动与支架（模板、示例） |

## 3.7 四要素 × 三级量规【CSTA 材料第六节第 5 条】

| 要素 | 1 起步（相当于 MS） | 2 达标（相当于 HS 基础标准） | 3 进阶（相当于 S1 方向） |
|---|---|---|---|
| **分解** | 能把任务拆成步骤，把重复步骤封装为过程 | 能把复杂问题分解为模块（函数、库、对象），说明各模块的职责和交互 | 能考虑规模增长，设计可扩展的组件关系 |
| **模式识别** | 能发现明显趋势；判断问题适合用程序、规则还是数据方法 | 能在代码中找冗余并重构；在多变量数据中找关系；知道何时用正则 | 能解释模式、异常、趋势并给出替代解释；识别需要无监督学习的问题 |
| **抽象** | 能使用多种数据类型变量；伪代码中包含过程 | 能选择数据结构并说明理由；设计带参数和返回值的函数；编写数据字典 | 能综合运用数据抽象、过程抽象、递归和面向对象抽象 |
| **算法设计** | 能用给定输入验证算法正确性 | 能用指标或测试用例评估效率、正确性、清晰度；测试边界；审查 AI 代码；迭代改进 | 能对照设计规格系统评估，比较多种方案的权衡并说明选择理由 |

> 可另设"品格倾向"一栏（CSTA 的 Dispositions），如坚持（遇错误是否坚持调试）、反思（是否主动回顾）、批判性思维，用"总是 / 经常 / 偶尔"记录。

## 3.8 过程性评价工具【CSTA 材料第六节第 4 条】

| 工具 | 用法 | 看什么 |
|---|---|---|
| 设计日志 | 学生记录"测试→发现→修改" | 是否真实记录问题与改动 |
| 测试用例表 | 单元小测或项目附件 | 是否覆盖正常、边界、异常 |
| 版本提交记录 | `git log` | 分工是否均衡，提交说明是否清晰 |
| 出声思维 / 结对观察 | 抽样观察 | 是否先拆分？是否主动说"这和××一样" |
| 同伴评审 | 用学习材料"工具 6" | 评审意见是否具体、可操作 |
| 反思问卷 | 每单元末 3 题 | 坚持、反思、批判性思维 |

## 3.9 成绩构成建议【设计】

| 部分 | 占比 | 说明 |
|---|---|---|
| 形成性（学习单、微训练、日志） | 30% | 重完成度与过程 |
| 单元小测 | 20% | 四个单元各 5% |

# 四、分年级逐课时教学指引

> 每课时给出：**教学目标 / 准备 / 关键提问 / 易错点 / 预设答案要点 / 板书建议**。课时安排见《训练计划》。

## 4.1 高一

### L0　前测
- **准备**：打印问卷；草稿纸；关闭网络。
- **关键**：强调没有对错，不计成绩；巡视不提示。
- **后续**：一周内完成评分并生成每位学生的四要素剖面。

### L1　校园科技节怎么办
- **关键提问**："这些事里，哪些是同一类？""如果我把你的模块名改了，别人看得懂吗？"
- **易错点**：把九件事逐一当模块；模块名过于笼统（"其他"）。
- **预设答案**：前期策划 / 宣传报名 / 物资与人员 / 现场实施 / 总结反馈（见问卷第 1 题参考思路）。
- **板书**：大事 → 若干块 → 每块里有哪些事。

### L2　谁先谁后，谁能同时
- **关键提问**："什么叫'前置'？""最慢的一条路是哪条？"
- **预设答案**：关键路径 A→B→D→G，总工期 7 天；C、D、E 可并行；F 与 B 可并行。
- **拓展**：泡茶题答案 —— 烧水 8 分钟的同时洗杯子、取茶叶，总计 8 + 1 = **9 分钟**。
- **易错点**：把所有任务相加；忘记并行；箭头方向画反。

### L3　借一本书要几步
- **关键提问**："哪一步出错会导致后面全部白做？""哪些是'问'，哪些是'做'？"
- **预设答案**：问卷第 2 题参考答案（选书、扫码、查资格、查可借、更新记录、改状态、输出结果）。
- **易错点**：判断步骤没有"否"的出口；把"输出"当"输入"。

### L4　小组项目怎么分工
- **预设答案**：见问卷第 3 题评分要点（设计问卷后才能发放；发放与准备录入表可部分并行；录入后统计，统计后绘图分析；报告与课件可在分析基本完成后并行；最后统一检查整合）。
- **组织建议**：4 人组；每人拿一张任务卡，任务卡上"输入信息"一栏最容易被忽略，必须检查。
- **易错点**：分工均衡但忽略依赖，导致有人空等；缺负责人。

### L5　数列里的秘密
- **关键提问**："相邻两项差多少？差有规律吗？""第 6 项和 6 有什么关系？"
- **预设答案**：2,5,10,17,26 → 37；aₙ=n²+1（问卷第 4 题）。
- **课后微训练答案**：斐波那契，后一项 = 前两项之和，下一项 13。
- **易错点**：只猜答案（"感觉是 37"）说不出理由 → 要求写出差的序列。
- **练习 1 答案**：3,6,11,18,27 → 差 3,5,7,9 → 下一差 11 → **38**（aₙ=n²+2）。
- **练习 2 答案**：1,4,9,16 → aₙ=n²；2,6,12,20 → aₙ=n(n+1)。

### L6　食堂数据在说什么
- **预设答案**：高峰在 12:15 前后（52 人），上升段 11:30–12:15，下降段 12:15–13:00；原因可能是下课时间集中、班级顺序、窗口数量。
- **离群值讨论**：520 会使图被拉伸，其他点几乎看不出变化；发现方法——与相邻时间对比、检查录入、画图时看量级。
- **易错点**：只描述数字不给结论；把相关当因果。

### L7　重复的事交给循环
- **预设答案**：见问卷第 5 题——及格人数 3 人；伪代码含初始化、逐个读取、条件判断、计数、输出。
- **评分提示**（5 分，每个评分点 1 分）：得到 3 人；逐个处理；条件判断；计数；步骤完整逻辑正确。
- **练习 2 提示**：最高分初始值应取第一个成绩，不要取 0（为高二的边界讨论埋下伏笔）。
- **易错点**：忘记计数器初始化为 0；条件写成 `>60`（漏掉恰好 60）。

### L8　换个问题，还是这个办法
- **预设答案**：问卷第 6 题——判断条件换为"作业按时提交"，分类名称换为"按时提交组 / 未按时提交组"，结构不变。

### L9　哪些信息才有用

### L10　计算机怎么"看见"信息
- **预设答案**：13 → 1101₂；10110₂ → 22；解释编码解码规则一致才能还原。

### L14　找得更快：顺序与二分
- **预设答案**：问卷第 11 题——顺序查找最多 9 次；二分查找缩小范围；必须有序才能排除一半。

# 六、学生典型错误与干预策略

| 要素 | 典型表现 | 可能原因 | 干预策略 |

| 分解 | 把所有任务堆在一起 | 没有"归类"意识 | 用卡片分类，先分组再命名 |
| 分解 | 不知道从哪开始（反向自评题所描述） | 缺少"先问什么"的脚手架 | 提供启发问句：目标是什么？要交什么？最后一步是什么？ |

| 模式识别 | 把巧合当规律 | 数据太少 | 要求至少用 3 组数据检验 |
| 模式识别 | 看不出"这是同一类问题" | 只关注表面 | 归类卡活动：按"用什么方法解决"分类 |
| 抽象 | 什么字段都想收集 | 缺少目标意识 | 先写"功能清单"，再逐个字段问"哪个功能要用" |
| 抽象 | 被细节干扰（反向自评题） | 缺少过滤策略 | 练习"一句话描述问题"，删去所有修饰 |

| 算法 | 想到一步做一步（反向自评题） | 缺少整体规划 | 先要求写出开始、结束、关键判断 |
| 算法 | 只测一组数据 | 缺少测试意识 | 引入"边界四件套"：空、单个、极值、混合 |
| 算法 | 盲信 AI | 把 AI 当权威 | 让学生找出 AI 的一个错误；先写测试再运行 |
| 通用 | 抄袭或求助 AI 代做 | 畏难或功利 | 要求提交设计日志与口头讲解；小组内抽问 |

# 七、AI 工具使用规范

## 7.1 原则【设计，依据 CSTA HS-PRO-RD-18 对 AI 生成代码评估的要求】

1. **AI 是被审查对象，不是答案来源。**

4. **必须提交《AI 使用声明》**（学习材料工具 5）。

# 十二、多语言教学指引（Python 与 C++）

> 与计划第七部分配套。**全部为【设计】，不是 CSTA 材料或评测问卷原文。** 表中现象均在 Python 3.13 与 Apple clang 21（`g++ -std=c++17 -Wall -Wextra`）上实测。

## 12.1 语言选择决策表

| 你的情况 | 建议路径 | 理由 |
|---|---|---|
| 多数学生零基础，课时紧 | **A：全程 Python** | 语法负担小，课堂时间留给分解与抽象 |
| 部分学生有竞赛基础，教师两种语言都会 | **B：Python 为主，C++ 组做对照** | 同题双语能让学生看清“语言差异”与“思维不变” |
| 竞赛班，教师以 C++ 为主 | **C：全程 C++** | 数据分析、机器学习、绘图课时改用 Python 或不插电 |
| 机房没有 C++ 环境 | A | 对照库的 C++ 代码仅供教师阅读 |

**原则**：不插电课时（高一 L1–L6、L8–L9、L11 等）不分语言；设计文档、测试用例表在两种语言下**同格式**。

## 12.2 课堂组织

| 事项 | 做法 |
|---|---|
| 同班两种语言 | 每组选一个“语言负责人”，负责环境与编译命令；设计环节全班统一进行 |
| 时间 | C++ 组编译与调试需要更多时间，可把“从键盘读入”等环节改为课后任务（计划 7.8） |
| 提交物 | 两种语言都提交：设计日志、测试用例表、源代码、运行截图 |
| 同伴评审 | 允许跨语言评审，评审重点是**逻辑与测试**，不挑语法 |

## 12.3 逐课时的语言易错点

| 年级 / 课时 | 现象 | Python | C++ | 教学处理 |
|---|---|---|---|---|
| 高一 L7、L16 | 求平均 | `sum / len` 得小数 | `sum / n` 是整数相除，需 `(double)` | 让学生先**预测**，再运行，再解释（实测：5 个数和为 326，C++ 得 65，Python 得 65.2） |
| 高一 L10 | 二进制转换 | `//` 整除 | `/` 对整数即整除 | 强调“两种写法算法相同” |
| 高一 L13 | 队列与堆栈 | 只要求认识用法 | 同左 | **不要求实现链表、栈、树**（CSTA 边界）；评价看选型理由 |
| 高一 L14 | 二分 | `(lo+hi)//2` | `(lo+hi)/2` | 记录比较次数，不讲 Big-O |
| 高一 L15 | 交换 | `a, b = b, a` | 临时变量或 `swap` | 先写临时变量版本，再给简写 |
| 高一 L16 | 空数据 | 抛 `ZeroDivisionError` 或返回 `None` | 小数除 0 得 `inf`/`nan`，不报错；整数除 0 为未定义行为 | 空数据必须写进测试用例表 |
| 高二 L11 | 越界 | 立即报 `IndexError` | `[]` 不检查，`.at()` 抛 `out_of_range` | 演示“没报错但结果不可信”；让学生设计能暴露越界的测试 |
| 高二 L13 | 计时 | `time.perf_counter()` | `<chrono>`；**`-O0` 与 `-O2` 差异极大** | 实测 n=10⁶ 求最大值：Python 约 0.017 s，C++ `-O0` 约 0.0054 s，`-O2` 约 0.00007 s（因机器而异）。要求学生写明语言、编译选项、数据规模、测量方法 |
| 高二 L14–L15 | AI 代码审查 | 初始值设为 0 导致全负数出错 | 同 | 先让学生自己设计测试，再运行 |
| 高三 L10、L13 | 随机数 | `random` | `mt19937` | 两种语言数值不同，规律一致；不要拿数值互相比对 |
| 高三 L11 | 封装 | `_` 前缀只是约定 | `private` 由编译器强制 | 引导学生体会“接口与实现” |

**不要写进课堂材料的一点**：我们曾试验“漏写 `#include <vector>`”能否让 C++ 报错，结果**在本机 libc++ 上并不报错**（`<iostream>` 间接包含了它），换成其他编译器可能报错。因此不要把它当作“必然报错”的例子，也不要告诉学生“不写头文件也行”。

## 12.4 编译报错的教学处理

1. **让学生只读第一条**：说出“第几行、什么问题、编译器给了什么建议”。
2. **教师不要立刻替学生改**：先问“编译器说了什么？你觉得是哪里？”
3. **使用 `-Wall -Wextra`**，让“未初始化变量”等警告也被看见。
4. **区分三类问题**：编译不通过（语法）、运行报错（运行时）、**运行不报错但结果错（逻辑）**。第三类最危险，也最需要测试用例。
5. 常见报错及真实措辞见学生材料附录 F。**报错文字会因编译器版本而不同**，上课前在机房环境确认一遍。

## 12.5 评价是否分语言

| 评价维度 | 是否分语言 | 说明 |
|---|---|---|
| 分解、模式识别、抽象、算法设计（三级量规） | **不分** | 量规对两种语言完全相同 |
| 实现完成度（程序能运行） | 单独记录，**不计入四要素等级** | 避免“选难语言被扣分” |
| 读报错与调试 | 课堂观察记录 | 记录是否能从第一条报错定位 |
| 测试与迭代（CT9） | **不分**，但 C++ 组应覆盖越界、整数除法等语言相关用例 | 用例是否覆盖语言特有的风险，属于“测试设计”质量 |
| 问卷前后测 | 不分 | 问卷本身不涉及具体语言 |

**警惕两种偏差**
- 不要因为 Python 写起来短，就降低对 Python 学生测试用例的要求；
- 不要因为 C++ 编译报错多，就认为 C++ 学生“思维弱”。

## 12.6 教师备课核对

- [ ] 在学生实际使用的机器上，把对照库对应课时的 Python 与 C++ 示例各运行一遍；
- [ ] C++ 环境确认 `-std=c++17` 已生效（结构化绑定需要）；
- [ ] Windows 中文乱码已处理（`chcp 65001` 或用英文输出）；
