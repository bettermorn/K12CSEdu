# 高中计算思维三年训练计划（高一 / 高二 / 高三）

> **适用对象**：高中一至三年级学生（约 15–18 岁）
> **理论框架**：计算思维 = **分解问题 + 模式识别 + 抽象 + 算法设计**
> **依据材料**
> - 《四要素视角下的高中计算思维：学习行为与评价方法》（依据 CSTA《2026 PK–12 Computer Science Standards》，以下简称"**CSTA 材料**"）
> - 《高中生计算思维能力评测问卷》（自评 20 题 + 情境能力测试 14 题，能力测试满分 85 分，以下简称"**评测问卷**"）
>
> **来源标注约定**：【CSTA】= 标准条目编号；【问卷】= 评测问卷题号；【设计】= 本计划依据教学经验的设计，不是上述两份材料的原文。
> **配套文件**：`2-学习材料.md`（学生用）、`3-教师手册.md`（教师用）、`4-Python与C++对照代码库.md`（Python 与 C++ 可运行示例，见第七部分）

## 一、总体设计

### 1.1 三年目标一句话

| 年级 | 年龄 | 主题 | 一句话目标 | 对应水平【设计】 |
|---|---|---|---|---|
| **高一** | 15–16 岁 | **看清问题** | 会把任务拆开、找规律、用符号和状态表示问题、写出清晰的步骤 | 水平 1 起步 → 向水平 2 过渡（相当于 CSTA 初中到高中的衔接） |
| **高二** | 16–17 岁 | **做好零件** | 会用模块、函数、数据结构和数据字典组织方案，会测试、重构、审查 AI 代码 | 水平 2 达标（相当于 CSTA 高中基础标准 HS） |
| **高三** | 17–18 岁 | **解决真问题** | 会定义复杂问题、用数据与模型找规律、权衡多种方案、协作完成跨学科项目 | 水平 2 稳固 → 向水平 3 进阶（接近 CSTA 专业方向 S1） |

> 水平 1/2/3 与 CSTA 材料第六节第 5 条的"起步 / 达标 / 进阶"三级量规一致，评分细则见《教师手册》。

### 1.2 设计原则

1. **螺旋上升**：四要素每年都出现，但任务的复杂度、数据规模、协作程度逐年增加（见 1.4 进阶表）。
2. **先不插电、再上机**：每个概念先用纸笔、卡片、流程图理解，再用 Python 实现。没有编程基础的班级，高一以流程图和伪代码为主，Python 为选做。
3. **过程重于答案**：评测问卷第八部分明确提出"重视过程，不只看最终答案""允许多种合理答案"，本计划把设计日志、测试记录、评审记录都纳入评价。
4. **不超出标准边界**：CSTA 高中基础标准**不要求 Big-O**，不要求实现链表、栈、树。因此"效率"用**实测运行时间或步数**比较，"队列 / 堆栈"只要求能为场景选型并说明理由。
5. **AI 是被审查的对象，不是答案来源**：高二起学习审查 AI 生成的代码（HS-PRO-RD-18）。课堂规定见《教师手册》第七节。
6. **贯穿工程设计过程**【CSTA p30】：定义问题 → 找模式 → 抽象 → 设计算法 → 测试改进 → 迁移。每个年级的综合项目都按这六环节走一遍。

### 1.3 课时与节奏

| 项目 | 安排 |
|---|---|
| 每年级总课时 | **18 课时**（前测 1 + 教学 16 + 后测与展示 1），每课时 45 分钟 |
| 建议节奏 | 每周 1 课时，一学期完成；也可隔周 1 课时，分散在一学年 |
| 单元结构 | 4 个单元，每单元 4 课时，对应四要素之一；第 4 单元末课时为综合项目 |
| 课后微训练 | 每课时配 1 道 10 分钟以内的微训练（见《学习材料》），可选做 |
| 设备 | 高一：纸笔 + 少量机房课；高二、高三：每人一台能运行 Python 3 的电脑 |

### 1.4 四要素 × 年级进阶表

| 要素 | 高一（看清问题） | 高二（做好零件） | 高三（解决真问题） |
|---|---|---|---|
| **分解** | 把活动、流程拆成子任务；区分串行与并行；写输入—处理—输出；小组分工 | 把程序拆成函数 / 模块并定义接口；画系统图、网络图；设计文档 + 基础版本控制 | 先定义问题、成功标准和约束；按多个维度拆分（对象 × 影响）；设计可随规模扩展的组件；团队评审 |
| **模式识别** | 数列规律；数据趋势和离群值；重复步骤→循环；二分类结构迁移 | 代码中找重复并重构；多变量数据找关系；正则表达式匹配文本格式；识别误导性图表 | 解释模式、异常、趋势并给出替代解释；训练并评价机器学习模型；识别规则和数据中的偏见模式 |
| **抽象** | 提取关键字段；二进制编码；状态表示；用变量、列表、字典表示对象 | 选择数据结构并说明理由；编写数据字典；过程抽象（参数、返回值）；生成仿真数据 | 建模时说明保留和忽略的变量；仿真与参数实验；面向对象表示复杂实体；理解分层与接口 |
| **算法设计** | 队列 / 堆栈选型；顺序查找与二分查找；设计比较交换排序；写简单测试用例 | 实测比较两种算法；设计覆盖边界的测试用例；审查 AI 生成的代码；迭代改进并记录 | 比较确定性与随机算法；选择 AI 算法并说明理由；对照设计规格系统评估；根据用户反馈改进 |

### 1.5 评价节奏

| 时间 | 工具 | 作用 |
|---|---|---|
| 学年开始（第 0 课时） | **评测问卷前测**（30–40 分钟，自评 + 能力测试） | 摸底分层，与后测对比 |
| 每课时 | 学习单、课后微训练 | 形成性反馈 |
| 每单元末 | 单元小测（4 要素之一）+ 设计日志抽查 | 判断该要素是否达到本年级目标 |
| 学年末（第 17 课时） | **评测问卷后测** + 综合项目档案袋与展示 | 终结性评价，前后测增量分析 |
| 三年累计 | 三份档案袋 + 三次前后测 | 看三年成长曲线 |

> 问卷使用要点（来自问卷第八部分）：不只看自评；自评和能力测试要对照；对有编程基础的学生，可把第 5、11、12 题改写成 Python 程序。

## 二、高一年级计划：看清问题（15–16 岁）

### 2.1 学情与目标

- **学情**：多数学生编程经验有限（问卷基本信息中"是否学习过编程"可用来分层）。擅长具体操作，抽象符号表达较弱，容易"想到哪一步就做哪一步"（问卷第 19 题反向题所描述的行为）。
- **年度目标**【设计，依据 CSTA 初中→高中衔接】
  1. 分解：能把一件事拆成 4 个以上合理子任务，并指出先后和并行关系；
  2. 模式识别：能从数列和数据中发现规律，会用"如果……那么……""重复……直到……"描述规则；
  3. 抽象：能区分关键信息与无关细节；能用二进制、状态表、变量表示对象；
  4. 算法设计：能写出步骤完整、顺序合理的算法，会用测试数据检验。

### 2.2 单元安排

| 单元 | 课时 | 主题 | 主要产出 |
|---|---|---|---|
| 单元 1 分解 | L1–L4 | 把大任务拆开 | 任务依赖图、借书流程图、小组分工表 |
| 单元 2 模式识别 | L5–L8 | 在数字和数据里找规律 | 规律说明书、趋势图、条件+循环伪代码、问题归类卡 |
| 单元 3 抽象 | L9–L12 | 留下关键、去掉细节 | 字段选择说明、二进制转换表、状态转移表、数据表示方案 |
| 单元 4 算法设计 | L13–L16 | 把方法写清楚并检验 | 队列堆栈选型表、查找与排序算法、测试用例表、班级成绩小助手 |
| 前后测 | L0、L17 | 问卷前测 / 后测与展示 | 问卷、成果展示 |

### 2.4 高一阶段性达标标准【设计】

- 问卷能力测试百分制得分比前测提高；
- 分解维度：能独立完成问卷 Q1 类任务并得 6 分以上（满分 8）；
- 模式识别：能用伪代码正确完成问卷 Q5 类任务；
- 抽象：能正确完成十进制与二进制互转，能为功能选出必要字段；
- 算法设计：能独立写出三数排序步骤，并说明二分查找为什么要求有序。

## 三、高二年级计划：做好零件（16–17 岁）

### 3.1 学情与目标

- **学情**：已有一定 Python 或其他语言基础（若全班无基础，建议先补 6–8 课时 Python 基础再进入本计划）。会写简单程序，但容易写成"一大段"，不会测试，对 AI 生成的代码盲目信任。
- **年度目标**【CSTA 高中基础标准 HS】
  1. 分解：能创建模块化程序，每个模块用一个函数、库或对象实现（HS-PRO-PD-12）；
  2. 模式识别：能在代码中找冗余并重构（HS-ALG-PS-02）；能清洗文本数据并用正则表达式匹配（HS-DAT-DC-23）；能可视化多变量数据并识别误导性图表（HS-DAT-DI-25、HS-DAT-DI-26）；
  3. 抽象：能选择数据结构（HS-ALG-PS-01）、编写数据字典（HS-DAT-DC-22）、用过程抽象优化算法；
  4. 算法设计：能用指标和测试用例评估算法（HS-ALG-PS-03）；能审查 AI 生成的代码并测试边界情况（HS-PRO-RD-18）；能依据测试结果改进（HS-PRO-TR-20）。

### 3.2 单元安排

| 单元 | 课时 | 主题 | 主要产出 |
|---|---|---|---|
| 单元 1 分解 | L1–L4 | 模块化与协作 | 模块结构图、函数接口说明、系统图、设计文档与提交记录 |
| 单元 2 模式识别 | L5–L8 | 代码与数据里的模式 | 重构前后代码、多变量图表、正则表达式、图表评审单 |
| 单元 3 抽象 | L9–L12 | 数据与过程的抽象 | 数据结构选择论证、数据字典、通用函数、仿真数据 |
| 单元 4 算法设计 | L13–L16 | 评估、测试与改进 | 算法对比实验报告、测试用例集、AI 代码审查报告、"图书漂流"项目 |
| 前后测 | L0、L17 | 问卷前测 / 后测 | 问卷、成果展示 |

## 七、多语言训练方案：Python 与 C++

> **本部分定位**：前六部分的课时、产出和评价**与语言无关**；本部分说明同一课时用 Python 或 C++ 完成时，各自要教什么、怎么练、容易错在哪里。
> **配套代码**：全部课时的可运行示例见《4-Python与C++对照代码库》，同一任务两种语言各一份，均已在本机编译或运行通过（Python 3.13；Apple clang，`g++ -std=c++17 -Wall -Wextra`，零错误零警告）。
> **来源标注**：本部分全部为【设计】，不是 CSTA 材料或评测问卷的原文。CSTA 材料不规定使用哪种语言。

### 7.1 总原则：语言是工具，四要素才是目标

1. **评价看思维，不看语法**。量规（起步 / 达标 / 进阶）对两种语言完全相同；语法错误单独记录，不计入四要素等级。
2. **同一课时同一产出**：学生用哪种语言，都要交同样的设计日志、测试用例表和模块结构图。
3. **先想后写**：任何编程课时，先写自然语言或伪代码，再翻译成代码。这样 Python 组和 C++ 组的思维产出可以直接对照。
4. **每年只教够用的语法**，见 7.4。语法点超出清单的，放入"挑战任务"，不放入必修。
5. **不要求 Big-O**（依据 CSTA 高中基础标准）。比较效率只用实测运行时间，并写明语言、编译选项、数据规模。

### 7.2 三种实施路径

| 路径 | 适用情况 | 做法 | 需要注意 |
|---|---|---|---|
| **A：全程 Python（推荐默认）** | 学生多数零基础；课时紧；无信息学竞赛需求 | 三年都用 Python，C++ 只在高三选修或社团出现 | 高二、高三的数据、仿真、机器学习课时只有 Python 路径最完整 |
| **B：Python 起步，高二加入 C++ 对照** | 有一定基础；有信息学竞赛或强基计划方向的学生 | 高一 Python；高二起 C++ 组在同一课时做"对照任务"，其余同学继续 Python | 教师需要同时会两种语言；C++ 组每个编程课时需要多约 10–15 分钟编译与调试时间【设计，按实际调整】 |
| **C：全程 C++（竞赛班）** | 竞赛班、教师以 C++ 为主 | 高一用 C++ 最小子集；数据与机器学习课时（高二 L6–L8、L12）建议改用 Python 或改为不插电分析 | 高一 L7、L12 起步更陡，需减少每课时的任务量；正则表达式、绘图在 C++ 里不适合高中课堂 |

**选择建议**
- 默认选 A。理由：Python 的语法噪声少，学生能把课堂时间花在分解和抽象上。
- 选 B 或 C 的班级，仍然要保证"不插电"课时（高一 L1–L6、L8–L11，高二 L1–L4 等）**不分语言**，全班一起上。
- 同一班级内允许两组学生用不同语言，但**设计文档和测试用例表必须同格式**，便于同伴互评。

### 7.3 环境与工具

| 项目 | Python | C++ |
|---|---|---|
| 推荐环境 | Thonny（零基础）；VS Code + Python 扩展（进阶）；IDLE（备用） | VS Code + g++；Dev-C++ 或 Code::Blocks（机房已有时） |
| 运行命令 | `python3 文件名.py`（Windows：`python 文件名.py`） | `g++ -std=c++17 -Wall -Wextra -o 程序名 文件名.cpp`，再运行 `./程序名`（Windows：`程序名.exe`） |
| 必须设置 | 无 | 编译标准设为 C++17（Dev-C++ 在"编译选项"中加 `-std=c++17`）；打开 `-Wall` 警告 |
| 中文输出 | 一般没问题 | Windows 控制台可能乱码：先执行 `chcp 65001`，或让输出用英文 |
| 版本管理 | 两种语言相同：`git init / add / commit / log` | 同左 |
| 第一周必做 | 运行 `print("你好")` | 运行"Hello"程序，并**故意**删掉一个分号，读第一条报错 |

**课前检查清单（两种语言通用）**
- 每台机器先跑一遍对照库的 `g1_*` 示例，确认环境可用。
- C++：确认编译命令里没有遗漏 `-std=c++17`，否则结构化绑定（`auto [a, b]`）会报错。
- 带输入的程序先在命令行测试：`echo "55 60 72 48 90 -1" | ./程序名`。

### 7.4 各年级语言知识清单（"够用"原则）

#### 高一：只学能表达算法的最小子集

| 内容 | Python | C++ |
|---|---|---|
| 变量与输出 | `x = 5`；`print(x)` | `int x = 5;`；`cout << x << endl;`（需 `#include <iostream>`） |
| 输入 | `input()`、`int()`、`split()` | `cin >> x;`，循环读入到哨兵值 |
| 条件 | `if / elif / else`，缩进 | `if / else if / else`，花括号 |
| 循环 | `for x in 列表`；`while` | `for (int x : v)`；`while` |
| 列表 / 数组 | `list` | `vector<int>`（`#include <vector>`） |
| 字典 | `dict` | `map<string,int>`（`#include <map>`，高一只在 L12 点到为止） |
| 函数 | `def f(a, b):` | `int f(int a, int b) { ... }` |
| 队列与堆栈 | 只认识用法（`collections.deque`、`list.append / pop`） | 只认识用法（`queue`、`stack`） |

**高一不教**：类、指针、模板、递归、排序库函数的内部原理、Big-O。引用参数只在 L15 出现一次（`void sort3(int& a, int& b, int& c)`），用来说明“函数里交换，外面的变量跟着变”，不要求学生自己设计引用参数。

#### 高二：加入模块化、数据与测试

| 内容 | Python | C++ |
|---|---|---|
| 函数接口 | 默认参数、返回多个值 | 引用参数、`const vector<int>&`、返回 `pair` / 结构体 |
| 异常处理 | `try / except / raise` | `try / catch / throw`；对比 `[]` 与 `.at()` |
| 数据结构选择 | 列表套字典、字典 | `vector<结构体>`、`map` |
| 文件与文本 | `open`、`split`、`re` | `<fstream>`、`getline`；`<regex>` 仅作演示 |
| 测试 | `assert`、手写测试表 | `assert`（`<cassert>`）、手写测试表 |
| 计时 | `time.perf_counter()` | `<chrono>`，**必须同时记录 `-O0` 或 `-O2`** |
| 简单可视化 | `matplotlib`（高二 L6、L8） | 不推荐，改为输出数据，由 Python 或表格软件画图 |

#### 高三：项目所需的进阶语法

| 内容 | Python | C++ |
|---|---|---|
| 类 | `class`、`__init__`、方法；`_` 前缀约定隐藏 | `class`、构造函数、`private / public`，编译器强制 |
| 随机数 | `random` | `<random>`（`mt19937`）；数值与 Python 不同，规律相同 |
| 仿真 | 列表模拟队列 | `vector`、`queue` |
| 机器学习 | 手写 K 近邻；有条件时用 `scikit-learn` | 手写 K 近邻（见对照库） |
| 项目组织 | 多个 `.py` 文件 + `import` | 多个 `.cpp` / `.h` 文件（竞赛班可选） |

### 7.5 逐课时语言训练细节

> 表中"对照库任务"指《4-Python与C++对照代码库》中的同名条目。"不分语言"表示该课时不插电或语言无关，全班一起上。

#### 高一（水平 1→2）

| 课时 | 对照库任务 | Python 训练要点 | C++ 训练要点 | 语言相关易错点（均已实测） |
|---|---|---|---|---|
| L1–L6 | — | 不分语言 | 不分语言 | — |
| **L7** 重复的事交给循环 | 成绩统计；从键盘读入成绩 | 用 `for` 逐个处理 5 名学生，`count += 1` 计数；读入到 `-1` 结束 | 同一逻辑；先写出 `#include`、`main`、`int` 声明，再写循环；用 `cin` 读到 `-1` | C++ 求平均：`sum / n` 是**整数相除**（`7/2=3`），要写成 `(double)sum / n`；Python 的 `/` 总是小数 |
| L8–L9 | — | 不分语言 | 不分语言 | — |
| **L10** 二进制 | 十进制与二进制互转 | 用 `//` 和 `%` 反复除 2；字符串反转 `[::-1]` | 用 `/` 和 `%`；`string` 拼接后 `reverse` | Python 用 `//`，C++ 的 `/` 对整数就是整除；两个答案相同，但原因不同 |
| L11 | — | 不分语言（状态转移表） | 不分语言 | — |
| **L12** 变量、列表、字典 | 对照库未单列此课时（L16 的成绩小助手中有 `vector` 的用法可参考） | `list`、`dict` 表示通讯录 | `vector`、`map<string,string>` | C++ 容器要先声明元素类型，迫使学生想清楚"这个量是什么" |
| **L13** 队列与堆栈 | 队列与堆栈 | 只认识用法，说明"先进先出 / 后进先出" | 用 `queue` / `stack`，只调用 `push / pop / front / top` | **不要求实现链表、栈、树**（CSTA 边界）；只考选型 |
| **L14** 顺序与二分 | 顺序查找、二分查找 | 记录比较次数；二分前先排序 | 同一逻辑；注意 `mid` 的整数除法 | 不要求 Big-O，用"比较次数"说明差别 |
| **L15** 自己设计排序 | 三数排序 | 先用比较和交换写三数排序，再推广到四个数；可用 `a, b = b, a` | 先用临时变量交换，再介绍 `swap(a, b)` | 先理解"临时变量"，再接受简写 |
| **L16** 成绩小助手 | 班级成绩小助手 + 测试用例表 | 6 步流程；测试表含空数据、恰好 60 分 | 同一表格；空数据时 C++ 要先判断 `size() == 0`，否则除以零 | Python 除以零报 `ZeroDivisionError`；C++ 整数除以零是**未定义行为**，结果因平台而异（本机实测：不报错，得到 0）；小数相除时 `5.0 / 0` 得到 `inf`、`0.0 / 0` 得到 `nan`，也不报错。**不能指望程序自己报错，要靠测试用例和先判断 `empty()` 来避免**（见对照库“高二 L11 下标越界与除以零”） |

### 7.6 语言专项训练：三类通用练习

**（1）读第一条报错**（高一 L7 起，每周 5 分钟）
让学生只读第一条报错，说出"哪一行、什么类型的问题"，再改。以下为本机真实报错，可直接用作课堂材料：

| 类别 | 语言 | 真实报错信息 |
|---|---|---|
| 缺分号 | C++ | `expected ';' at end of declaration` |
| 变量名拼错 | C++ | `use of undeclared identifier 'totl'; did you mean 'total'?` |
| 类型不匹配 | C++ | `cannot initialize a variable of type 'int' with an lvalue of type 'const char[4]'` |
| 参数个数不对 | C++ | `no matching function for call to 'add'` |
| 未初始化变量 | C++（需 `-Wall`） | `variable 's' is uninitialized when used here` |
| 下标越界 | Python | `IndexError: list index out of range` |
| 除以零 | Python | `ZeroDivisionError: division by zero` |
| 变量未定义 | Python | `NameError: name 'total' is not defined` |
| 类型相加 | Python | `TypeError: can only concatenate str (not "int") to str` |
| 数据转换 | Python | `ValueError: invalid literal for int() with base 10: 'abc'` |
| 缩进错误 | Python | `IndentationError: expected an indented block after 'if' statement on line 1` |
| 语法错误 | Python | `SyntaxError: expected ':'` |

> 说明：报错文字因编译器和 Python 版本而异，上表来自 Apple clang 21 与 Python 3.13；学校机房的版本不同时，措辞可能不同。

**（2）同题双语对照**（B、C 路径，每单元一次）
同一个算法，让学生在两种语言里各写一次，填写下面的"差异卡"：

| 项目 | Python | C++ | 我的发现 |
|---|---|---|---|
| 变量需要声明类型吗 | | | |
| 整数相除 `7 / 2` 的结果 | | | |
| 下标越界时发生什么 | | | |
| 一段代码的行数 | | | |

**（3）边界测试清单**（所有路径）
每个函数至少测试：空输入、单个元素、全负数、重复值、最大最小值、非法输入。两种语言共用同一张测试用例表，C++ 组额外测试"越界读取"和"整数溢出"。

### 7.7 语言专项评价

| 维度 | 评价方式 | 是否计入四要素等级 |
|---|---|---|
| 分解、模式识别、抽象、算法设计 | 沿用三级量规，不分语言 | 是 |
| 能运行、无报错 | 提交可运行的代码或截图 | 否，单独记录为"实现完成度" |
| 读报错与调试 | 课堂观察 + 调试记录，记录学生能否从第一条报错定位问题 | 否 |
| 语言特性理解（整数除法、越界、类型） | 差异卡、测试用例表中是否包含针对性用例 | 仅当影响算法正确性时，计入算法设计的"测试与迭代" |

**原则**：学生不应因为选了较难的语言而在四要素上被扣分；也不应因为 Python 语法简单而在"测试与迭代"上得到更低要求。
