## 一、计算思维在课标中的定位

### 1. 定义（两份课标表述一致，侧重点略有不同）

| | 高中课标 [高] p5 | 义教课标 [义] p5 |
|---|---|---|
| 共同定义【原文】 | 个体运用计算机科学领域的思想方法，在问题解决过程中涉及的**抽象、分解、建模、算法设计**等思维活动 | 同左 |
| 学生表现【原文】 | 能**采用计算机可以处理的方式界定问题**、抽象特征、建立结构模型、合理组织数据；通过判断、分析与综合各种数据资源，运用恰当的算法形成解决问题的方案；**分析算法效率**，验证、反思和优化解决问题的方案，并将其迁移运用于其他问题的解决 | 能对问题进行抽象、分解、建模，并通过设计算法形成解决方案，能通过**模拟、仿真**等方式验证解决问题的过程，反思、优化解决问题的方案，并将其迁移运用于解决其他问题 |

【整理】两份课标都可以概括为一条思维链，高中阶段多了"计算机可处理的界定""组织数据""分析算法效率"三点：

> **界定问题 → 抽象特征 → 分解 → 建模 / 组织数据 → 设计算法 → 验证（测试）→ 反思优化（含效率分析）→ 迁移**

### 2. 高中计算思维的三级水平（[高] 附录 p57–58，【原文】）

| 水平 | 计算思维表现 | 对应要求 |
|---|---|---|
| **水平1** | ① 针对给定任务进行需求分析，明确关键问题，对问题进行抽象处理，**用形式化的方法表述问题**<br>② 运用算法思想设计解决问题的方案，能**使用程序或其他方式验证**这一方案，有意识规避算法应用的潜在风险<br>③ 选用恰当的数字化工具或方法采集、整理、分析和可视化呈现数据，**反思和优化**方案，并将其**迁移**到其他问题解决中 | 毕业要求，也是**合格性考试**的依据 |
| **水平2** | ① 针对较复杂任务，用形式化方法描述问题，采用**模块化和系统化**方法设计方案<br>② 针对具体问题进行**数据抽象**，合理组织、存储数据，设计算法并**编程实现**<br>③ 使用数据管理系统创建数据文件，对数据进行管理和应用<br>④ 设计智能化解决问题方案，利用人工智能开放平台搭建简单智能系统 | **等级性考试**命题不超过水平2 |
| **水平3** | ① 依据信息系统设计原则对较复杂问题的方案进行**较全面的评估**，**迭代优化**方案<br>② 通过计算**时空复杂度**，比较解决同一问题的不同算法<br>③ 把算法思想和方法迁移到学习和生活其他问题中 | 进阶水平，供特长发展、创新人才选拔参考 |

> 水平的用途见 [高] p40【原文】：水平1是毕业要求和合格考依据；等级考命题"不超过学业质量水平2，不应集中于水平1"；水平3供特长发展、选拔参考。

### 3. 衔接起点：义教第四学段（7–9 年级）

- **计算思维学段特征**（[义] 附录表10，p60，【原文】）
  1. 能在真实情境中发现问题，提取问题的基本特征，对问题进行抽象、分解、建模，制订解决方案；
  2. 能执行问题解决方案，通过对数据的采集与分析，反思和优化解决方案，并将其迁移运用于解决其他问题。
- **第三学段已具备的基础**（[义] 表2，p9；表5，p45）：用自然语言、流程图描述算法；使用顺序、分支、循环三种控制结构，并**通过编程验证**；能针对不同输入数据规模，比较不同算法的时间效率；利用反馈实现过程与控制。
- **第四学段的计算思维载体**：互联网（协议的分层与分解）、物联网（数据采集、传输、反馈控制）、人工智能（数据、算法、算力；搜索、推理、预测、机器学习）。

【整理】可见高一入学时，学生应已有"分解 + 三种控制结构 + 编程验证 + 初步效率比较 + 系统 / 反馈"的经验。高中阶段的增量集中在四处：**形式化描述、数据抽象与数据结构、模块化 / 系统化设计、时空复杂度分析与迭代优化**。

### 3. 课标倡导的学习方式

- 【原文】**"尝试 — 验证 — 修正"活动发展学生计算思维**（[高] p42，教学建议 (3)）。这是高中课标中唯一一处直接点名"发展计算思维"的学习方式。
- 【原文】以**项目主题**组织教学内容，针对真实性问题情境，**运用学科思维形成解决问题的方案**，再利用数字化平台实施；组建学习小组，在交流互助中提升学科思维（[高] p42）。
- 【原文】从实际问题入手，让学生**分析问题、建立数学模型、将其形式化、用计算机语言编程解决**，"注重思路和方法的引导，以利于学生计算思维的形成和发展"（[高] 选修1 教学提示，p33）。
- 【原文】"做中学""用中学""创中学"（[高] p42；[义] p3）。
- 【原文】义教课标："场景分析 — 原理认知 — 应用迁移"；引导学生经历"原理运用过程、**计算思维过程**和数字化工具应用过程"（[义] p3、p48）。
- 【原文】开源硬件项目中"把大部分时间留给学生去探索，通过**多次迭代**的过程完善项目设计"（[高] 选必6 教学提示 (2)）。

【整理】可以归纳出一个课堂学习循环：

> **真实情境 → 需求分析与形式化 → 分解 / 建模 → 设计算法（流程图 / 伪代码）→ 编程或用 AI 实现 → 测试验证 → 效率与合理性评估 → 修正迭代 → 迁移到新问题**
>
> 其中"尝试 — 验证 — 修正"是贯穿全程的核心小循环。

## 三、评价计算思维的方法

### 1. 课标规定的评价框架（【原文】）

**评价原则**（[高] p43–44）
- 发挥评价的激励、诊断和促进作用；"注意**观察学生实际的技术操作过程及活动过程**，分析学生**典型的信息科技作品**"。
- 面向全体学生，注重"不同起点上的提高"，多用**表现性评价语言**，不能简单以分数或等级评估。
- **过程性评价与终结性评价相结合**；用**电子作品档案袋**、**学习平台记录表**等记录学习状况。
- 情境贴近学生的学习和生活，注重信度和效度。

**评价目标的确定**（[高] p44）：综合考虑**学科核心素养、学业质量标准、模块内容要求与学业要求**。面向素养的评价"尤其要关注**情境的设计**"。

**评价方式**（[高] p45）

| 方式 | 适用范围（课标原意） |
|---|---|
| 纸笔测试 | 效率高，适合考基础知识；应控制客观题比例，**增加问题解决分析、作品设计等开放性题目** |
| 计算机环境下的测试 | 终结性评价**不可或缺**；考查利用信息科技解决问题的能力 |
| 日常教学中的项目实践 | 过程性评价，手段包括**课堂观察、学习行为分析、作品评价、档案袋资料采集** |

**义教课标补充的评价环节**（[义] p49–50，【原文】）
- 过程性评价要求情境真实、主体多元（学生、教师、家长）、方式多样（观察、实验、**模拟、仿真**、纸笔、**上机实践**、作品创作）、内容全面（知识技能、**思维过程**、情感态度），反馈要有指导性。
- **课堂评价**：观察、提问、记录。
- **作业评价**：任务实践类（电子作品、仿真实验、系统搭建）和原理认知类（数据分析、现象解释、实验报告），并做分层设计。
- **单元与期末评价**：结合课堂表现和平时作业。
- 学业水平考试形式：纸笔测试、上机实践、**自适应测评**。

### 2. 考试中如何考计算思维（[高] p46–50，【原文】）

- **考试形式**：合格考以**计算机环境下的考试为主**，结合纸笔考试和项目实践；等级考鼓励有条件的地区上机考试。
- **题型**：选择、填空、解答、实践操作。合格考中**解答题和实践操作题分值占比不少于 50%**。
- **任务设计**：
  - "注重引导学生**运用计算思维识别与分析问题，抽象、建模与设计系统性解决方案**，运用数字化手段实施方案、解决问题。"这是课标对考查计算思维的最直接表述。
  - **开放性**：鼓励不同的解题思路，"展现其个性化的思维过程，为解决同一问题预留**多样化作答结果**的空间"，避免只考机械记忆。
  - **综合性**：将不同素养要素相互关联，不按单一模块做线性设计。
- **评分要求**：
  - **分级赋分选择题**：按选项反映的素养水平赋予不同分数；
  - 填空题：客观内容用精确匹配，主观内容用**模糊匹配**；
  - 解答题：制定评分标准，明确**分数等级、特征表现、分数解释与作答样例**，提供不同水平学生的实际作答样例；
  - 实践操作题：关注**任务达成度、完成时长、操作过程的规范性**。
- **项目作品评价维度**（[高] 选必6 教学提示 (3)）：**创新性、实用性、解决问题的效果**。

**义教样题示例**（[义] p51–54）
- 纸笔题"智慧停车"：识别 AI 环节、说明摄像头作用、分析系统**可采集哪些数据**（系统分析）。
- 上机题"空气质量"：**设计统计表**（数据建模）→ 处理数据 → 选择合适图表 → 根据数据**阐述结论并说明理由**。

### 3. 可直接作为评价依据的行为证据【整理】

| 思维环节 | 可观察 / 可收集的证据 | 收集途径 |
|---|---|---|
| 界定与抽象 | 需求分析记录、形式化描述（变量、约束、输入输出）、数据结构选择理由 | 解答题、项目设计书 |
| 分解与建模 | 模块图或功能结构图、调用关系、数据库 E-R 图或表结构 | 作品、设计文档 |
| 算法设计 | 流程图、伪代码、程序 | 纸笔题、上机题 |
| 验证测试 | 测试用例与结果、调试记录、AI 生成代码的核验记录 | 上机题、平台日志、档案袋 |
| 效率评估 | 不同算法的运行时间对比、时空复杂度分析 | 解答题、实验报告 |
| 反思优化 | 版本迭代记录、"尝试 — 验证 — 修正"日志、优化前后对比 | 档案袋、学习平台记录 |
| 迁移 | 用同一思想解决新情境问题的表现 | 开放题、变式题 |
| 负责任应用 | 对算法风险、AI 局限的分析 | 解答题、讨论记录 |

### 4. 基于课标水平改写的评分量规【整理】

依据 [高] 附录的计算思维水平1–3 改写，可用于解答题、项目作品和档案袋的整体评分：

| 维度 | 水平1（合格） | 水平2（良好 / 等级考） | 水平3（进阶） |
|---|---|---|---|
| 问题表述 | 能对**给定任务**做需求分析，用形式化方法表述关键问题 | 能对**较复杂任务**做形式化描述，并进行**数据抽象** | 面对综合任务，能分析关键要素及其相互关系，建立结构模型 |
| 方案设计 | 运用算法思想设计方案，并用流程图或伪代码描述 | 采用**模块化、系统化**方法设计；能合理选择数据结构和算法 | 能依据信息系统设计原则进行全面规划 |
| 实现与验证 | 用程序或其他方式（含生成式 AI）验证方案有效性 | 编程实现，并能使用数据管理系统 / AI 平台搭建系统 | 应用 AI 等新技术验证和优化方案 |
| 评估与优化 | 感受算法效率，根据测试结果优化 | 分析算法效率，评判数据结构运用的合理性 | 计算**时空复杂度**，比较不同算法，**迭代**优化 |
| 迁移与责任 | 有意识规避算法风险，能把方案迁移到相似问题 | 把方案迁移到其他问题，遵守算法伦理规范 | 把算法思想迁移到学习和生活中，负责任地设计与应用算法 |

## 四、要点小结

1. **定义**：两份课标对计算思维的定义一致，都是"抽象、分解、建模、算法设计"。高中阶段增加了"计算机可处理的界定""组织数据""分析算法效率"。
2. **学习行为主线**：需求分析 → 形式化 → 分解 / 模块化 → 数据结构建模 → 算法设计与表示 → 程序或 AI 验证 → 效率评估 → 迭代优化 → 迁移和规避风险。
3. **学习方式**：项目教学，以及课标点名的 **"尝试 — 验证 — 修正"**；选修课强调"问题 → 数学模型 → 形式化 → 编程"。
4. **评价**：
   - 依据三级水平（水平1 合格、水平2 等级考、水平3 进阶）；
   - 方式上，过程性与终结性相结合，纸笔、上机、项目实践并用，用档案袋和平台记录学习过程；
   - 考试中，合格考以上机为主，解答题和实践操作题不少于 50%，任务要求"运用计算思维识别与分析问题，抽象、建模与设计系统性解决方案"，并保留开放作答空间；
   - 评分方式包括分级赋分选择题、带作答样例的等级评分标准，以及按任务达成度、完成时长、操作规范性评价实践题。
5. **与 CSTA 2026 的差异**【整理】：CSTA 以实践（CT6 定义问题、CT7 抽象、CT8 创造、CT9 测试改进）组织，**标准本身不规定评价方式**；中国课标则**自带学业质量水平、评价建议和考试建议**，评价体系更完整，但对"测试用例""调试"等具体行为的描述比 CSTA 少。两者可以互补：用中国课标的水平和考试框架，配合 CSTA 的细粒度行为描述。
