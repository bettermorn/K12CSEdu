### ——依据高中、义教两份信息科技课标（教师用）

## 〇、先厘清：四要素与课标表述的对应关系

两份课标给出的定义相同（[高] p5，[义] p5）【原文】：

> 计算思维是指个体运用计算机科学领域的思想方法，在问题解决过程中涉及的**抽象、分解、建模、算法设计**等思维活动。

| 题目四要素 | 课标中的对应表述 | 说明 |
|---|---|---|
| 分解问题 | 分解；模块化、系统化；"大系统由小系统组成" | 直接对应 |
| **模式识别** | **课标未使用"模式识别"一词**。相近的原文有：发现规律；不同系统中存在**相似**的组成部分；**总结归纳**关键要素；**提炼**特性；迁移到**类似**问题；同一问题的多种算法 | 【映射】分散在多处，需要教师有意识地组织 |
| 抽象 | 抽象特征；形式化描述；数据抽象；**建模**；建立结构模型 | 课标把"建模"单列，本文并入抽象 |
| 算法设计 | 算法思想、算法描述、编程验证、效率分析、优化 | 直接对应，也是课标中篇幅最多的部分 |

此外，课标把**验证 — 反思优化 — 迁移**作为计算思维的后续环节。本文将其放在算法设计和模式识别中处理。

## 一、分解问题

### 1. 学段进阶【原文】

| 阶段 | 课标表述 |
|---|---|
| 义教 3–4 年级 | 把问题划分为多个可解决的小问题，通过解决各个小问题实现整体问题解决（[义] p9） |
| 义教 5–6 年级 | 将给定任务分解为一系列实施步骤；将问题分解为可处理的子问题；一个大的系统可以分解为几个小的系统，一个系统也可以划分出功能相对独立的多个模块（[义] p9、p30） |
| 义教 7–9 年级 | 体会互联网如何把复杂的远程通信问题"逐步化简为分解、编码、传输和重新组合等一系列规则（协议）"；TCP/IP 如何将复杂问题"一步步分层、分解，直至细化到网络设备和具体算法能处理的程度"（[义] p35–36） |
| **高中** | 采用**模块化和系统化**方法设计解决问题的方案（[高] 水平2，p58；学业质量 2-2，p39） |

### 2. 高中学习行为

| 学习行为 | 出处 |
|---|---|
| 设计作品方案时，描述各组成部分及其功能，**明确各组成部分之间的调用关系** | [高] 选必6 内容要求 6.3，p30 |
| 把移动应用开发拆成一组小任务，再串成综合任务（记事本：纯文本 → 格式 → 表格图像 → 网络存储） | [高] 选修2 教学提示 (3)，p36 |
| 对综合性任务分析**关键要素及相互关系**，建立结构模型 | [高] 学业质量 3-1，p39 |
| 剖析信息系统的输入、计算、输出过程 | [高] 必修2 内容要求 2.2，p15 |
| 按照"提出想法 → 设计系统方案 → 实现 → 迭代优化"的阶段推进项目 | [高] 选必6 教学提示 (3)，p31 |

【映射】课堂上可以落实为：画功能结构图或模块图，写出模块之间的接口（输入 / 输出），按子任务分工实现，最后集成测试。

## 二、模式识别

### 1. 课标中的相关原文【原文 + 映射】

| 模式识别的含义 | 课标原文 | 出处 |
|---|---|---|
| 识别不同系统的**共同结构** | "能发现大的系统可以由小的系统组成，**不同的系统中存在相似的组成部分**。能识别系统中的输入、计算、输出环节" | [义] 5–6年级 过程与控制 学业要求，p31 |
| 从多个案例中**归纳共同要素** | 剖析"校园一卡通""在线选课""网络订票"等系统，"**总结归纳**信息系统的关键要素" | [高] 必修2 教学提示 (1)，p16 |
| 对比中**提炼**特性 | 与同类传统应用对比，"发现并逐步**提炼**其中的网络特性" | [义] 7–9年级，p37 |
| 从数据中**发现规律** | 用数据记录并描述**规律性发生的事件**；数字气象站"探寻数据的变化**规律**，尝试得到**一般性的结论**"，"发现规律的一般过程" | [义] p24、p43 |
| 识别问题**类型**，以选择对应的结构或方法 | 根据数据特点和应用需求合理选择数据结构（字符串、队列、栈）；车库单行道"后进先出"→ 栈 | [高] 选必1 内容要求 1.5、例1，p18–19 |
| 识别算法**范式** | 掌握贪心、分治、动态规划、回溯等常见算法 | [高] 选修1 内容要求 1.5，p33 |
| 数据中的**分类与聚类** | 探索分类、回归、聚类等数据分析方法 | [高] 选必3 内容要求 3.7，p23 |
| 将已识别的模式**迁移**到类似问题 | 汉诺塔"迁移到其他生活场景的**类似问题**中"；把算法思想迁移到学习和生活中；能把方案迁移到其他问题 | [义] p33；[高] 选修1 1.7，p33；水平1-3、水平3-3，p57–58 |

### 2. 高中学习行为【映射】

1. **多案例比较**：分析 2–3 个同类系统（如一卡通、选课、订票），列出共同的输入、处理、输出和数据要素。
2. **问题归类**：先判断"这是哪一类问题"，例如先进后出、先进先出、查找、最优选择、可拆成相同子问题，再选择对应的数据结构或算法范式。
3. **数据找规律**：对采集的数据做可视化、分类和聚类，用规律支撑结论或预测。
4. **复用与迁移**：把已解决问题的方法改造后用于新问题，并说明"哪里相同、哪里需要改"。

> **教师提示**：模式识别在课标中没有独立条目，是四要素中最容易被教学忽略的。建议在每个单元安排至少一次"对比归纳"或"变式迁移"活动。

## 三、抽象（含建模）

### 1. 课标中的进阶【原文】

| 阶段 | 课标表述 |
|---|---|
| 义教 5–6 年级 | 过程与控制"可以**抽象为**包含输入、计算和输出三个典型环节的系统"；连续量可以经由**阈值**判断形成开关量（[义] p30） |
| 义教 7–9 年级 | 在真实情境中发现问题，**提取问题的基本特征**，对问题进行抽象、分解、建模（[义] 表10，p60） |
| 高中水平1 | 明确需要解决的关键问题，对问题进行抽象处理，**用形式化的方法表述问题**（[高] p57） |
| 高中水平2 | 针对具体问题进行**数据抽象**，合理组织、存储数据（[高] p58） |
| 高中水平3 | 分析关键要素及相互关系，**建立结构模型**（[高] 学业质量 3-1，p39） |

### 2. 高中学习行为

| 学习行为 | 出处 |
|---|---|
| 经历描述问题，**并用符号语言将其形式化**的过程；理解"解决问题的起点是问题的描述，算法的基础是形式化描述" | [高] 选修1 内容要求 1.1，p33 |
| 从实际问题**建立数学模型**，将其形式化，再编程解决 | [高] 选修1 教学提示，p33 |
| 将有限制条件的复杂生活情境中的关系进行抽象，**用数据结构表达数据的逻辑关系** | [高] 选必1 学业要求，p19 |
| 用二维数组表示围棋棋盘（0 空 / 1 甲 / 2 乙） | [高] 选必1 例2，p19 |
| 理解**抽象数据类型**的概念及其作用 | [高] 选必1 内容要求 1.6，p18 |
| 设计关系数据库的逻辑结构（实体、属性、关系） | [高] 选必3 内容要求 3.4，p23 |
| 理解计算机中**数据编码**的基本方式 | [高] 必修1 内容要求 1.1，p12 |
| 根据事物特点进行一定的抽象，设计符合事物特性的系统 | [高] 选必6 学业要求，p32 |

【映射】课堂上可以落实为：写清输入、输出和约束；判断"保留什么、忽略什么"；选定数据表示方式（变量、数组、表、栈、图）。

## 四、算法设计

### 1. 课标中的进阶【原文】

| 阶段 | 课标表述 |
|---|---|
| 义教 5–6 年级 | 用自然语言、流程图描述算法；用顺序、分支、循环描述实施过程，并**通过编程验证**；针对不同的输入数据规模，比较不同算法的时间效率（[义] p9、p45） |
| 高中水平1 | 运用算法思想设计方案，**用程序或其他方式验证**，有意识规避算法应用的潜在风险（[高] p57） |
| 高中水平2 | 设计算法并**编程实现**；分析算法效率（[高] p58，p39） |
| 高中水平3 | 计算**时空复杂度**，比较同一问题的不同算法；采用**迭代**思想评估和优化方案（[高] p58，p39） |

### 2. 高中学习行为

| 学习行为 | 出处 |
|---|---|
| 概述算法的概念、特征和控制结构，**综合运用流程图、伪代码**表示算法 | [高] 必修1 内容要求 1.4，p12 |
| 针对具体问题设计算法，**通过程序、生成式人工智能等方式验证**，感受算法效率 | [高] 必修1 内容要求 1.5，p12 |
| 通过"辗转相除法""割圆术"体验算法设计与实现；分组探究三种控制结构 | [高] 必修1 教学提示 (3)，p13 |
| 用排序、查找体验**迭代与递归** | [高] 选必1 内容要求 1.7，p18 |
| 描述斐波那契数列、秦九韶等经典算法；掌握贪心、分治、动态规划、回溯并编程实践 | [高] 选修1 内容要求 1.3、1.5，p33 |
| 比较解决同一问题的不同算法；理解算法的**正确性、可读性、健壮性**；会计算时空复杂度 | [高] 选修1 内容要求 1.6，p33 |
| 根据测试结果优化方案 | [高] 学业质量 1-2，p38 |
| 遵守算法设计的伦理规范，有意识规避算法风险 | [高] 学业质量 2-2，p39 |

## 五、贯穿四要素的学习方式【原文】

- **"尝试 — 验证 — 修正"活动发展学生计算思维**（[高] 教学建议，p42）。这是高中课标中唯一点名发展计算思维的学习方式。
- **项目教学**：针对真实情境，运用学科思维形成方案，再用数字化平台实施；小组合作（[高] p42）。
- **"问题 → 数学模型 → 形式化 → 编程"**，并"注重思路和方法的引导"（[高] p33）。
- **"场景分析 — 原理认知 — 应用迁移"**（[义] p48）；"做中学、用中学、创中学"。
- 开源硬件项目中"通过**多次迭代**的过程完善项目设计"（[高] p31）。

**一节课中四要素的组织示例【映射】**（以"食堂排队优化"为例）

| 环节 | 要素 | 学生活动 |
|---|---|---|
| 1 | 分解 | 把"减少排队时间"拆成三个子问题：到达规律、窗口服务、调度规则 |
| 2 | 模式识别 | 对比银行叫号、医院挂号，发现它们都是"先进先出队列 + 多服务台"的结构；从采集到的数据中找出高峰时段 |
| 3 | 抽象 | 只保留到达时刻、服务时长、窗口数，用队列表示排队，写出输入、输出和约束 |
| 4 | 算法设计 | 写伪代码模拟两种调度规则，编程运行并比较平均等待时间 |
| 5 | 验证与修正 | 用实测数据检验模拟结果，修正参数后迭代 |
| 6 | 迁移 | 把同一模型用于"图书馆借还书"或"停车场"场景 |

## 六、评价计算思维的方法

### 1. 课标规定的评价框架【原文】

| 方面 | 要点 | 出处 |
|---|---|---|
| 评价依据 | 核心素养 + **学业质量标准（水平1–3）** + 模块内容要求与学业要求 | [高] p44 |
| 评价原则 | 激励、诊断、促进；**观察技术操作过程和活动过程**、分析典型作品；用表现性评价语言，关注不同起点上的提高 | [高] p43–44 |
| 过程与终结 | 二者结合；用**电子作品档案袋**、**学习平台记录表**记录学习过程 | [高] p44 |
| 评价方式 | **纸笔测试**（增加问题解决分析、作品设计等开放题）+ **计算机环境下的测试**（终结性评价不可或缺）+ **项目实践**（课堂观察、学习行为分析、作品评价、档案袋） | [高] p45 |
| 过程性评价环节 | 课堂评价（观察、提问、记录）；作业评价（任务实践类和原理认知类，分层布置）；单元与期末评价；评价内容包括**思维过程** | [义] p49–50 |
| 考试任务设计 | "注重引导学生运用计算思维**识别与分析问题，抽象、建模与设计系统性解决方案**"；预留**多样化作答**空间，"展现其个性化的思维过程" | [高] p49 |
| 题型与分值 | 合格考以上机为主，**解答题和实践操作题分值不少于50%** | [高] p47 |
| 评分 | 选择题**按选项反映的素养水平分级赋分**；填空题主观内容用**模糊匹配**；解答题给出**分数等级、特征表现和作答样例**；实践题看**任务达成度、完成时长、操作规范性** | [高] p50 |
| 作品评价维度 | 创新性、实用性、解决问题的效果 | [高] p31 |

### 2. 按四要素设计的评价方法与题型【映射】

| 要素 | 可收集的证据 | 推荐评价方式 | 题目示例 |
|---|---|---|---|
| **分解** | 模块图、子任务清单、模块之间的调用关系与接口 | 纸笔解答题；项目设计书评审 | "为校园图书借阅系统画出功能模块图，并说明各模块之间传递的数据" |
| **模式识别** | 共同点和差异对比表、问题归类理由、数据规律及其证据、迁移说明 | **对比题、变式题、迁移题**；数据分析上机题 | "给出订票、选课、挂号三个系统，归纳它们的共同结构"；"下列哪个问题可以用栈解决？说明理由" |
| **抽象** | 输入 / 输出 / 约束描述、变量与数据结构选择、E-R 图、"保留与舍弃"的理由 | 解答题（形式化描述）；数据库设计上机题 | "用二维数组表示井字棋棋盘，并写出判断胜负所需的数据"；义教样题"设计空气质量统计表"（[义] p53） |
| **算法设计** | 流程图或伪代码、程序、测试用例与结果、复杂度分析、迭代记录 | 上机实践题；程序阅读与改错；**同一问题多算法的效率对比** | "分别用顺序查找和二分查找实现，比较 n=10³、10⁶ 时的比较次数" |
| **综合** | 完整项目过程记录 | 项目档案袋 + 答辩；"尝试 — 验证 — 修正"日志 | 选必6"温度监测调控系统"（[高] p30） |

**过程性观察清单（课堂可勾选）【映射】**

- [ ] 动手前先拆分任务或画结构图（分解）
- [ ] 主动指出"这和之前的××问题很像"（模式识别）
- [ ] 能说清输入、输出、约束，并合理选择数据表示（抽象）
- [ ] 先写伪代码或流程图再编码；准备测试用例（算法设计）
- [ ] 出错后定位原因并修改，而不是随意改代码（尝试 — 验证 — 修正）
- [ ] 能比较两种方案的优劣（效率、可读性、健壮性）
- [ ] 能把方法用到新情境（迁移）

### 3. 四要素 × 三级水平评分量规【映射，水平依据 [高] 附录 p57–58、学业质量 p38–40】

| 要素 | 水平1（合格，毕业要求） | 水平2（良好，等级考上限） | 水平3（进阶，特长发展） |
|---|---|---|---|
| **分解** | 能把给定任务拆成若干步骤或子问题 | 能用**模块化、系统化**方法设计方案，说明模块之间的关系 | 对综合任务分析关键要素及相互关系，依据系统设计原则做整体规划 |
| **模式识别** | 能在教师提示下发现相似问题，套用已学方法；从数据中读出明显趋势 | 能**自主归类**问题，并据此选择合适的数据结构或算法；能把方案迁移到其他问题 | 能识别跨领域的共同结构，主动把算法思想迁移到学习和生活中 |
| **抽象** | 能明确关键问题，用**形式化方法**表述问题 | 能进行**数据抽象**，合理组织和存储数据（数组、链表、栈、队列、数据库表） | 能建立**结构模型**，并说明抽象中取舍的依据 |
| **算法设计** | 能运用算法思想设计方案，用流程图或伪代码描述，用程序或其他方式（含 AI）验证；有风险意识 | 能编程实现，并分析算法效率；遵守算法伦理 | 能计算**时空复杂度**、比较不同算法，采用**迭代**方法评估和优化 |

> 用法：每个要素按 1–3 级评分，同时记录证据（截图、伪代码、日志）。过程性评价看进步幅度，终结性评价看所达水平。

## 七、给教师的要点

1. 课标原文使用"抽象、分解、**建模**、算法设计"。题目框架中的"**模式识别**"在课标中**没有对应条目**，但可以从"发现规律、相似组成部分、总结归纳、提炼、问题归类、迁移"等表述中找到依据，需要教师有意识地设计活动和评价。
2. 高中阶段在义教基础上的主要增量是：**形式化描述、数据抽象与数据结构、模块化系统设计、复杂度分析与迭代优化**。
3. 学习方式的核心是 **"尝试 — 验证 — 修正"** 和项目学习。
4. 评价采用三级水平，过程性与终结性相结合，纸笔、上机、项目并用；考试强调"识别与分析问题，抽象、建模与设计系统性解决方案"，并允许开放作答。
