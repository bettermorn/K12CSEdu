# 中美课标比较：提升高中生计算思维的学习行为与评价方法
### ——四要素视角（分解问题 · 模式识别 · 抽象 · 算法设计）（教师用）

> **比较对象**
> - 中国：《普通高中信息科技课程标准（2017年版2025年修订）》，记作 **[高]**；《义务教育信息科技课程标准（2022年版2025年修订）》，记作 **[义]**（扫描版，文字经 OCR 识别）
> - 美国：CSTA《2026 PK–12 Computer Science Standards》，记作 **[CSTA]**。以高中基础标准 HS 为主，MS 作为起点，S1/S2 作为拓展
> - 页码均为印刷页码
>
> **标注**：【原文】为课标原句或直译；【整理】为本文的归纳、比较或推论，不是课标原有表述。

## 〇、一页结论

| | **相同** | **不同：中国** | **不同：美国** |
|---|---|---|---|
| CT 定义 | 都包含分解、抽象、算法；都把计算思维放在"真实问题解决"中 | "**抽象、分解、建模、算法设计**"（[高] p5），**没有"模式识别"一词** | 计算思维是 4 项实践 CT6–CT9（p30）；**CT7a 明确提出"提取共同特征和模式"**；S1-XCS-XC-02 同时写出四要素（p155） |
| 学习方式 | 项目式、真实情境、迭代改进、迁移、用 AI 辅助并验证 | "**尝试 — 验证 — 修正**"（[高] p42）；"问题 → 数学模型 → 形式化 → 编程" | 工程设计过程："定义问题 → 开发方案 → 测试、改进、优化"（p30）；协作工作流和版本控制 |
| 算法深度 | 都要求比较同一问题的不同算法 | 选修1 要求**计算时空复杂度**，掌握贪心、分治、动态规划、回溯（[高] p33） | HS **不要求 Big-O**，用**实测指标和测试用例**评估（HS-ALG-PS-03，p39） |
| 评价体系 | 都重视过程性评价、作品评价和上机实践 | **规定完整**：水平1–3、合格考和等级考、题型比例、评分规则（[高] p43–50、p57–58） | **不规定评价方式**（p4）；只通过边界说明和内嵌检验手段给出评价依据，另有**品格倾向**维度 |

## 一、框架层面的比较

| 维度 | 中国课标 | CSTA 2026 | 比较【整理】 |
|---|---|---|---|
| 组织方式 | 核心素养（信息意识、计算思维、数字化学习与创新、信息社会责任）+ 模块内容要求 + **学业质量水平** | 概念领域（ALG、PRO、DAT、SYS、SOC 等）× **实践 CT6–9** + **品格倾向（Dispositions）** | 中国按"素养水平"分级，美国按"实践"和"具体表现"列出 |
| CT 的位置 | 四大核心素养之一，有独立的水平1–3 描述（[高] p57–58） | 贯穿各领域的实践，每条标准都标注所涉及的实践 | 中国是"素养目标"，美国是"行为规格" |
| 粒度 | 模块级的内容要求，较概括 | 条目级，每条附**边界说明**（Boundary Statement）和示例 | 美国更细，并写明"不要求什么" |
| 层级 | 必修（全体）→ 选择性必修 → 选修；水平1 为毕业要求，等级考不超过水平2 | HS 基础（全体）→ S1/S2 专业方向（S1 146 处、S2 124 处标准行） | 两者都有"共同基础 + 分流拓展"的设计 |
| 四要素的显性程度 | 分解、抽象、算法直接出现；**模式识别没有出现**；"建模"单列 | **四要素全部显性**（CT6c、CT7a、CT8/9；S1-XCS-XC-02、MS-SOC-CE-44） | 中国教师需要自己组织模式识别活动 |

## 二、按四要素比较学习行为

### 1. 分解问题

| | 中国 | 美国 |
|---|---|---|
| 核心表述【原文】 | 用**模块化和系统化**方法设计方案（[高] 水平2，p58）；描述各组成部分的功能和**调用关系**（选必6 6.3，p30） | 把复杂问题分解为可处理的部分，**每部分实现为独立的过程、库或对象**（HS-PRO-PD-12，p52）；CT6c |
| 典型情境 | 信息系统"输入 — 计算 — 输出"剖析（必修2，p15）；TCP/IP 分层（[义] p35–36）；移动应用逐级拆分（选修2，p36） | 游戏中把移动和计分分开实现；网络图（HS-SYS-NT-34，p83）；互联网分层（NT-35，p84）；安全事件按利益相关者分类（SE-32，p81） |
| 协作 | 小组合作的项目教学（p42） | **设计文档 + 角色分工 + 基础版本控制**（HS-PRO-PD-15，p53） |

- **相同【整理】**：都从"系统 → 子系统 / 模块"入手，都用网络分层作为典型案例，都要求说明模块之间的关系。
- **不同【整理】**：中国偏向**系统设计视角**，强调关键要素、相互关系和结构模型。美国偏向**软件工程落地**，要求分解结果落实为函数、库或对象，并用设计文档和版本控制管理分工。

### 2. 模式识别（差异最大的一项）

| | 中国 | 美国 |
|---|---|---|
| 是否显性 | **没有"模式识别"一词**。相关表述分散在：不同系统有**相似**组成部分（[义] p31）、**总结归纳**关键要素（[高] p16）、**提炼**网络特性（[义] p37）、发现**规律**（[义] p24、p43）、迁移到**类似**问题（[义] p33；[高] p33、p57–58） | **显性**：CT7a"Extract common features and **patterns**"（p30）；MS-ALG-PS-04 "**pattern-based rules**"（p38） |
| 对象 | 系统结构、数据规律、问题类型（栈 / 队列，[高] p18–19）、算法范式（贪心 / 分治等，p33）、分类与聚类（选必3，p23） | 代码**冗余**（HS-ALG-PS-02，p39）、文本**正则匹配**（HS-DAT-DC-23，p67）、多变量数据关系（DI-25，p70）、ML 模型（ML-08，p44）、**偏见模式**（IM-10，p47）、异常与趋势（S1-DSC-MI-07，p126） |
| 定位 | 偏向"归纳 → 迁移"，服务于方法复用 | 作为抽象的第一步，"形成通用方法和算法" |

- **相同【整理】**：都要求从数据中发现规律，都重视把已有方法迁移到新问题。
- **不同【整理】**：
  1. 美国把"**人识别模式**"（数据分析、代码重构）和"**机器识别模式**"（机器学习）并列，还要求识别**有害模式**（算法偏见）。中国的相关内容主要在数据分析和人工智能模块中。
  2. 美国有**代码层面**的模式识别（找冗余并重构、正则表达式），中国课标对此没有明确要求。
  3. 中国通过"**问题归类 → 选择数据结构或算法范式**"体现模式识别，算法范式的深度高于美国 HS。

### 3. 抽象（含建模）

| | 中国 | 美国 |
|---|---|---|
| 核心表述【原文】 | 用**形式化方法**表述问题（水平1，p57）；**数据抽象**（水平2，p58）；建立**结构模型**（3-1，p39）；用符号语言形式化（选修1 1.1，p33）；**抽象数据类型**（选必1 1.6，p18） | 选用合适的**数据结构**（HS-ALG-PS-01，p38）；**过程抽象**（PS-02，p39）；参数和返回值（PRO-RD-17，p58）；**数据字典**（DAT-DC-22，p66）；建模仿真（CT7c） |
| 数据结构深度 | 字符串、队列、栈，以及抽象数据类型，并结合情境选择（车库 → 栈；二维数组表示棋盘，p18–19） | 数组、列表、字典；**HS 不要求实现链表、栈、树**（HS-PRO-VD-16 边界说明，p56） |
| 建模 | "问题 → **数学模型** → 形式化 → 编程"（p33）；关系数据库 E-R 设计（选必3，p23） | 仿真数据生成（DC-21，p66）；规则模型和数据模型；分层抽象（操作系统，HW-29，p77） |

- **相同【整理】**：都把"选择合适的数据表示"当作抽象的核心行为，都包含建模和分层抽象。
- **不同【整理】**：中国更**数学化和形式化**（符号语言、数学模型、抽象数据类型），理论深度更高。美国更**工程化**：过程抽象（函数封装）和数据字典（数据文档）是显性要求。

### 4. 算法设计（含验证与优化）

| | 中国 | 美国 |
|---|---|---|
| 表示 | 流程图、伪代码（必修1 1.4，p12） | 流程图、伪代码（MS-ALG-PS-02；S1-XCS-XC-02） |
| 验证 | 用**程序、生成式人工智能**等方式验证（必修1 1.5，p12） | **测试用例**、**边界情况**、**审查 AI 生成的代码**（HS-PRO-RD-18，p58–59）；对照**设计规格**（TR-19，p61） |
| 效率 | 选修1：**时空复杂度**、多算法比较（p33）；水平3（p58） | 用**指标或测试用例**比较效率、正确性和清晰度；**不要求 Big-O**（HS-ALG-PS-03，p39） |
| 算法范式 | 迭代与递归（选必1，p18）；**贪心、分治、动态规划、回溯**（选修1，p33）；经典算法（辗转相除、割圆术、秦九韶） | 确定性与随机算法（PS-04，p39）；选择 AI 算法类型并说明理由（ML-06，p43）；递归在 S1（S1-SWD-DD-02，p149） |
| 迭代 | "尝试 — 验证 — 修正"（p42）；根据测试结果优化（1-2，p38） | 根据测试结果**和用户反馈**改进（TR-20，p62）；记录修改（MS-PRO-TR-19，p61） |
| 伦理 | 有意识规避算法风险，遵守伦理规范（2-2，p39） | 识别算法偏见（IM-10，p47） |

- **相同【整理】**：都采用"设计 → 实现 → 验证 → 迭代"的闭环，都要求比较不同算法，都把 AI 纳入验证环节，都关注算法风险。
- **不同【整理】**：
  1. **理论深度**：中国有复杂度分析和经典算法范式，并融入数学文化（如割圆术）。美国 HS 用实测代替理论分析，把深度放到 S1 方向。
  2. **验证方式**：中国说"用程序、AI **验证**"，AI 是验证工具。美国说"**审查** AI 生成的代码"，AI 是被检验的对象，学生用测试用例判断它对不对。
  3. **评估标准**：美国明确提出效率、正确性、**清晰度**，并加入**用户反馈**。中国提出正确性、可读性、健壮性（选修1 1.6）。

### 5. 学习行为相同点与不同点汇总

| 相同【整理】 | 不同【整理】 |
|---|---|
| 真实情境 + 项目式学习 | 中国："尝试 — 验证 — 修正"、**数学化建模**；美国：**工程设计过程**、协作工作流 |
| 先设计（流程图 / 伪代码）后编码 | 中国：形式化描述、复杂度分析；美国：数据字典、测试用例集 |
| 迭代优化 + 迁移 | 中国迁移侧重"方法迁移到生活"；美国侧重"**跨学科建模**"（S1-XCS-XC-02） |
| 把 AI 纳入学习 | 中国：AI 作为验证手段；美国：**AI 作为审查对象**，并学习训练和评估模型 |
| 算法伦理 | 美国把偏见模式识别写成具体的学习行为 |

## 三、评价方法的比较

### 1. 制度层面

| 方面 | 中国【原文】 | 美国【原文】 |
|---|---|---|
| 是否规定评价 | **规定**：评价原则、方式、学业水平考试命题和评分（[高] p43–50） | **不规定**："do not prescribe… assessments"（p4） |
| 评价标尺 | 学业质量**水平1–3**：水平1 为毕业和合格考依据，等级考不超过水平2（p57–58） | 每条标准是"表现期望"，**边界说明给出考查上限**（如不考 Big-O） |
| 评价方式 | **纸笔测试 + 计算机环境测试 + 项目实践**（p45） | 标准中内嵌了检验手段：测试用例、准确率评估（CT9a）、指标（PS-03）、设计规格对照（TR-19）、用户反馈（TR-20）、代码评审（MS-PRO-TR-19） |
| 题型与分值 | 合格考以上机为主，**解答题和实践操作题不少于 50%**（p47） | 无 |
| 评分规则 | 选择题**分级赋分**；主观填空**模糊匹配**；解答题配**等级、特征和样例**；实践题看**达成度、时长、规范性**（p50） | 无 |
| 过程记录 | **电子档案袋**、学习平台记录（p44）；课堂、作业、单元评价（[义] p49–50） | 设计文档、修改记录、版本控制（PD-15、MS-PRO-TR-19） |
| 非认知维度 | 信息社会责任（作为素养，不针对 CT） | **品格倾向**：Critical Thinking、Persistence、Reflectiveness 等，**每条标准都有标注** |

### 2. 按四要素比较评价证据【整理】

| 要素 | 中国常见评价证据 | 美国常见评价证据 | 差异 |
|---|---|---|---|
| 分解 | 功能模块图、结构模型、方案设计书 | 模块化程序本身、设计文档、分工和提交记录 | 中国看**方案**，美国看**程序结构和协作过程** |
| 模式识别 | 归纳题、问题归类题、数据规律分析 | **重构题**（找冗余）、正则表达式、数据解读、偏见识别 | 美国的证据更具体，可以直接在代码中检验 |
| 抽象 | 形式化描述、数据结构选择、E-R 图 | 数据结构选择理由、**数据字典**、函数接口设计 | 中国偏形式化，美国偏文档化 |
| 算法设计 | 上机编程、程序阅读改错、**复杂度计算**、多算法比较 | **测试用例设计**、**效率实测报告**、**AI 代码审查**、迭代日志 | 中国偏理论分析，美国偏实证测试 |

### 3. 评价方法的相同与不同

- **相同【整理】**
  1. 都重视**过程性证据**（中国用档案袋，美国用设计文档和修改记录）。
  2. 都以**作品和上机实践**为主要证据，而不只靠纸笔记忆。
  3. 都支持**开放任务**：中国"预留多样化作答空间，展现个性化思维过程"（p49），美国强调多方案比较并说明理由（CT8a、ML-06）。
- **不同【整理】**
  1. **刚性程度**：中国有考试制度、水平和评分细则，可以直接用于命题。美国只给"做到什么"和"不要求什么"，具体评价交给州、学区和教师。
  2. **标尺形式**：中国用**素养水平**做纵向分级（1–3）。美国用**学段标准**做进阶（MS → HS → S1/S2），并用边界说明限定上限。
  3. **评价维度**：美国增加了**品格倾向**（坚持、反思、批判性思维）。中国评价 CT 时侧重认知表现。
  4. **检验方式**：美国把"测试用例、边界测试、用户反馈、AI 代码审查"写进标准本身，评价和学习合为一体。中国把评价集中写在"评价建议"和"学业水平考试命题建议"中。

## 四、给中国高中教师的借鉴建议【整理】

**保留中国优势**
1. 用水平1–3 量规和合格考、等级考框架做终结性评价，标尺清晰。
2. 保留"问题 → 数学模型 → 形式化"的抽象训练和复杂度分析（选修1），培养理论深度。
3. 继续采用"尝试 — 验证 — 修正"的课堂节奏。

**借鉴 CSTA 补短板**
1. **显性化模式识别**：每个单元至少安排一次"找重复代码并重构"或"多案例归纳共同结构"的活动，并纳入量规（对应 CT7a、HS-ALG-PS-02）。
2. **把"AI 验证"升级为"审查 AI"**：给出 AI 生成的代码，要求学生设计测试用例（含边界情况）找出缺陷（对应 HS-PRO-RD-18）。
3. **引入数据字典和设计文档**：作为抽象和分解的书面证据，可以放入档案袋（对应 HS-DAT-DC-22、HS-PRO-PD-15）。
4. **测试用例作为评价证据**：上机题除了"能运行"，还要求提交测试用例集和效率实测表（对应 HS-ALG-PS-03）。
5. **增加品格倾向记录**：用"总是 / 经常 / 偶尔"记录坚持调试、主动反思等表现，作为过程性评价的补充。
6. **借鉴边界说明**：为校本作业写明"本题不要求……"，避免超纲，也让评价更聚焦。

**融合示例：四要素中美融合评价表**

| 要素 | 终结性（中国框架） | 过程性（借鉴美国） |
|---|---|---|
| 分解 | 解答题：画模块图并说明调用关系（水平2） | 设计文档 + 分工记录 |
| 模式识别 | 归类题 / 迁移题 | 重构任务：找出冗余代码并封装 |
| 抽象 | 形式化描述题；数据结构选择题 | 数据字典 |
| 算法设计 | 上机实践 + 复杂度分析（选修1） | 测试用例集 + AI 代码审查报告 + 迭代日志 |
| 品格 | — | 坚持、反思记录 |

## 五、要点小结

1. **框架**：中美都包含分解、抽象和算法。**美国显性提出模式识别**（CT7a），中国没有这个词，用"归纳、规律、相似、迁移"间接表达，并把"建模"单列。
2. **学习行为**：两国都采用项目式学习和迭代改进。中国**偏数学化和理论化**（形式化、复杂度、算法范式），美国**偏工程化和实证化**（模块化程序、测试用例、数据字典、AI 代码审查、版本控制）。
3. **评价**：中国**有完整、刚性的评价体系**（水平1–3、考试题型比例、评分细则）。美国**不规定评价方式**，只在标准中内嵌检验手段和边界说明，并增加品格倾向维度。
4. **借鉴**：用中国的水平量规做终结性评价，用美国的测试用例、重构任务、AI 审查和数据字典做过程性证据，并为模式识别补上显性的学习活动和评价项。
