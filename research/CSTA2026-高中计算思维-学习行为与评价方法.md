# 基于《2026 CSTA PK–12 计算机科学标准》的高中生计算思维：学习行为与评价方法

> 资料来源：2026 CSTA PK–12 Computer Science Standards（共 218 页）。下文页码为文档印刷页码，标准编号为原文编号。
> 标注【原文】的是文档原意的翻译或转述；标注【整理】的是基于原文归纳推导出的内容，原文并未直接写出。

---

## 一、标准对“计算思维”的定位

**定义【原文，p.30】**：计算思维是一种思考问题的方式，即把问题和解决方案表述成信息处理主体（如计算机）能够帮助解决的形式。计算思维实践把计算机科学学习与**工程设计过程**连接起来：识别并定义计算问题 → 开发计算技术作为解决方案 → 反复测试、改进、优化。

**在标准体系中的位置【原文，p.17、p.29】**：
- 标准由三部分组成：**概念**（学生要知道什么）、**实践**（学生要做什么）、**品格倾向**（学生以什么心态学习）。
- 计算思维属于**实践**，共 4 项（CT6–CT9）。实践“贯穿所有概念”，是“到高中毕业时的目标成果”，需要**通过反复接触逐步形成**。
- 每条标准都会注明它对应哪些实践。在 46 条高中基础标准中，对应计算思维实践的次数分别是：**CT6 共 15 次、CT7 共 11 次、CT9 共 9 次、CT8 共 8 次**【整理，据原文统计】。

## 二、提升高中生计算思维的学习行为

### 1. CT6 定义计算问题（Define computational problems）

**实践要求【原文】**
- 识别可以用**规则驱动**、**数据驱动**（如机器学习）或两者结合的方法来解决的现实问题；
- 清楚说明**成功标准**，并识别**约束条件**；
- 把复杂问题**分解**成可处理的子问题。

**对应的高中学习行为【原文标准举例】**

| 学习行为 | 标准 | 原文中的例子 |
|---|---|---|
| 阅读代码，解释参数、返回值、数据结构各起什么作用 | HS-PRO-RD-17 | 解释猜数字游戏中 while 循环和 if/else 如何配合 |
| 先定好需求，再检验 AI 生成的代码是否满足 | HS-PRO-RD-18 | 对 AI 写的“求平均值”函数，测试空列表、单个值、正负混合等情况 |
| 说出确定性算法与概率性算法的区别 | HS-ALG-PS-04 | 比较按固定顺序查找和随机抽取查找 |
| 比较几种数据校验方法的优劣 | HS-DAT-DC-24 | 设计生日字段的格式和取值范围校验方案 |
| 针对系统的安全缺陷提出解决方案 | HS-SYS-SE-33 | 针对校园网钓鱼攻击，提出技术措施和非技术措施 |
| 用新兴技术为现实问题设计概念方案 | HS-SOC-ET-42 | 设计用 AI 分析卫星图像、监测森林砍伐的方案 |

### 2. CT7 建立与使用抽象（Develop and use abstractions）

**实践要求【原文】**
- 从数据、过程或现象中**提取共同特征和模式**，形成通用的方法和算法；
- 编写**可复用的模块和过程**，在多种场景中使用，以降低复杂度；
- 用规则驱动或数据驱动的方法**建模和仿真**，用来理解和评估可能的结果。

**对应的高中学习行为【原文标准举例】**

| 学习行为 | 标准 | 原文中的例子 |
|---|---|---|
| 为问题选择合适的数据结构并设计算法 | HS-ALG-PS-01 | 设计游戏排行榜：用列表存分数，再按从高到低排序 |
| 用过程抽象优化冗长重复的算法 | HS-ALG-PS-02 | 把重复的成绩计算封装成 calculateGPA 过程，再用循环处理 |
| 把程序拆成独立模块（过程、库、对象） | HS-PRO-PD-12 | 把游戏的移动逻辑和计分逻辑分开 |
| 用数组、列表、字典来组织数据 | HS-PRO-VD-16 | 编写存取学生姓名和成绩的程序 |
| 编写数据字典（字段名、类型、取值范围、字段间的逻辑关系） | HS-DAT-DC-22 | 为问卷数据写数据字典，说明跳题逻辑导致的缺失值 |
| 画出包含硬件和软件的网络结构图 | HS-SYS-NT-34 | 标出服务器、路由器、终端、操作系统和应用 |
| 论证为某项任务选择某类 AI 算法的理由 | HS-ALG-ML-06 | 解释垃圾邮件分类为什么适合用决策树（逻辑透明） |

### 3. CT8 创造计算技术（Create computing technologies）

**实践要求【原文】**
- **提出并评估多种解法**，在约束条件下选出最符合标准的方案；
- **规划**计算解决方案的开发过程；
- 通过传统编程、**模型训练**或两者结合来**实现**解决方案。

**对应的高中学习行为【原文标准举例】**

| 学习行为 | 标准 |
|---|---|
| 选择合适的数据和工具，训练并测试一个机器学习模型（如手写数字识别） | HS-ALG-ML-08 |
| 按以人为本的设计流程，设计一个可访问的产品（如注意对比度、支持键盘导航） | HS-ALG-IM-09 |
| 用计算工具生成符合指定参数的模拟数据（如抛体运动的初速度和角度） | HS-DAT-DC-21 |
| 为多变量数据制作可视化，用来回答问题或做预测 | HS-DAT-DI-25 |
| 跨学科应用：用伪代码或流程图，为其他学科的问题设计计算方案（如捕食者与猎物的种群模型） | S1-XCS-XC-02 |

### 4. CT9 测试与改进计算技术（Test and refine computing technologies）

**实践要求【原文】**
- **系统地**测试、调试、排错，方法要合适，例如为规则驱动的程序**设计测试用例**、对机器学习模型做**准确率评估**；
- **反复改进和优化**，直到达到成功标准。

**对应的高中学习行为【原文标准举例】**

| 学习行为 | 标准 | 原文中的例子 |
|---|---|---|
| 用指标或测试用例评估算法的效率、正确性和清晰度 | HS-ALG-PS-03 | 用不同长度的列表测试两种“找最大值”算法的运行时间 |
| 评估 AI 输出的准确性、偏见和潜在危害 | HS-ALG-PS-05 | 发现图像生成工具对某些群体表现不足 |
| 对照设计规格评估作品的正确性、有效性和用户体验 | HS-PRO-TR-19 | 测试多种输入，检查边界情况、可用性和可访问性 |
| 根据测试结果和用户反馈改进作品 | HS-PRO-TR-20 | 增加帮助命令、简化说明、调整字号和对比度 |
| 用计算工具清洗文本数据，判断哪里可以用正则表达式 | HS-DAT-DC-23 | 统一日期格式、去除重复、拆分姓名字段 |
| 借助文档、库、API 和 IDE 调试器开发程序 | HS-PRO-PD-13 | 直接调用数学库，而不是自己从头写三角函数 |

### 5. 支撑计算思维的配套学习行为【原文 + 整理】

- **迭代设计**（HCD11）：先做简单原型，再持续测试和改进。
- **用户参与**（HCD10）：在设计全过程中收集不同用户的意见和反馈。
- **协作开发**（IC4，HS-PRO-PD-15）：拆分任务、设定里程碑、维护设计文档、使用版本控制。
- **沟通与反思**（IC3、IC5c）：向不同对象讲清技术思路；反思自己的技术决策和团队互动。
- **品格倾向【原文，p.32】**：批判性思维、坚持、反思、善用资源等 7 种倾向，与**自我调节学习**（计划、监控、评估自己的成长）密切相关。

## 三、评价计算思维能力的方法

### 1. 先明确：标准本身不规定评价方式【原文，p.4】

> 标准描述的是学生在计算机科学中应当知道什么、能做什么，**并不规定**具体的课程、教学材料或**评价方式**。

因此，下面的评价方法分两类：一类是**标准里已经写明的评价依据和检验手段**，一类是**由此推导出的课堂评价设计**。

### 2. 标准中可以直接用于评价的依据【原文】

| 依据 | 怎么用于评价 |
|---|---|
| **标准表述（行为动词）** | 设计、优化、评估、分析、论证、创建……每个动词都对应一种可观察的表现性任务 |
| **边界说明** | 规定了达标需要做到什么、哪些**不要求**（如不要求大 O 分析、不要求形式化证明），用来划定评分范围、防止评价超纲 |
| **实践对应** | 每条标准注明对应 CT6–CT9 中的哪一项，可据此把题目归入计算思维的不同维度 |
| **学习进阶**（附录 C） | 对比初中到高中同一子概念的要求，用来判断学生处在哪个层级 |
| **资源**（网页版） | 原文说明网页版提供“经过审核的教学与**评价**资源” |

### 3. 标准中内嵌的检验手段【原文】

| 手段 | 出处 | 评价什么 |
|---|---|---|
| **测试用例 / 边界用例** | CT9a、HS-ALG-PS-03、HS-PRO-RD-18 | 学生能否系统地设计输入，验证程序是否正确 |
| **效率指标**（运行时间、内存）和**可读性** | HS-ALG-PS-03 | 比较不同算法，只要求定性或对比层面的分析 |
| **模型准确率评估** | CT9a、HS-ALG-ML-08 | 对数据驱动的解法做评估 |
| **模型拟合指标**（分类看准确率、精确率；回归看均方误差、R²）以及训练耗时 | 数据科学专项（p.132） | 进阶层面的量化评估 |
| **对照设计规格和成功标准** | CT6b、CT9b、HS-PRO-TR-19 | 作品是否达到事先说明的标准 |
| **用户反馈** | HCD10、HS-PRO-TR-20 | 改进是否有依据 |
| **评估 AI 生成的代码或内容** | HS-PRO-RD-18、HS-ALG-PS-05 | 批判性检验能力 |
| **评估算法在其他学科中的效果**（准确性、效率、适切性） | S1-XCS-XC-05 | 迁移应用能力 |

### 4. 推导出的课堂评价方式【整理】

| 评价方式 | 收集的证据 | 主要对应的实践 | 依据的标准 |
|---|---|---|---|
| **读代码并讲解** | 学生对一段代码如何运行的口头或书面解释 | CT6、CT7 | HS-PRO-RD-17 |
| **方案设计文档** | 问题陈述、成功标准、约束、子问题分解、伪代码或流程图 | CT6、CT8 | CT6b/c、S1-XCS-XC-02 |
| **项目作品** | 模块化程序、模型、数据可视化 | CT7、CT8 | HS-PRO-PD-12、HS-ALG-ML-08、HS-DAT-DI-25 |
| **测试报告** | 测试用例表（含边界情况）、测试结果、缺陷修复记录 | CT9 | HS-ALG-PS-03、HS-PRO-TR-19 |
| **迭代日志** | 每一版改了什么、为什么改（依据测试结果或用户反馈） | CT9、HCD11 | HS-PRO-TR-20 |
| **多方案比较与论证** | 两种以上解法的指标对比，以及最终选择的理由 | CT8a | HS-ALG-PS-03、HS-ALG-ML-06 |
| **审查 AI 输出** | 对 AI 代码的测试结论、偏见和错误分析 | CT6、CT9 | HS-PRO-RD-18、HS-ALG-PS-05 |
| **建模与抽象作品** | 数据字典、网络结构图、数据结构选择说明 | CT7 | HS-DAT-DC-22、HS-SYS-NT-34 |
| **跨学科任务** | 其他学科问题的计算化方案，以及对算法效果的评估 | CT6–CT8 | S1-XCS-XC-02、S1-XCS-XC-05 |
| **反思与自评** | 反思日志，以及计划—监控—评估的过程记录 | 品格倾向、IC5c | p.32 |
| **过程性观察** | 调试中是否坚持、是否主动查文档、是否请教他人 | 品格倾向 | 坚持、善用资源 |

**持续评价【整理】**：原文强调实践要“通过反复接触逐步形成”，所以计算思维更适合用**多次任务加作品集**的方式持续评价，而不是只靠一次考试。

### 5. 计算思维评价量规（示例）【整理】

| 维度 | 初步 | 达标（相当于高中标准要求） | 优秀 |
|---|---|---|---|
| **CT6 定义问题** | 能复述问题，但分解零散 | 写出成功标准和约束，把问题分解成合理的子问题 | 能判断该用规则驱动还是数据驱动的方法，并说明理由 |
| **CT7 抽象** | 代码重复多，没有封装 | 用过程或模块封装重复逻辑，并选用合适的数据结构 | 能提炼出通用方法，复用到新的场景，或做建模仿真 |
| **CT8 创造** | 只实现一种方案 | 按计划完成实现，至少比较过两种方案 | 在约束条件下有理有据地选出最优方案 |
| **CT9 测试与改进** | 只做零散的试运行 | 有系统的测试用例（含边界情况），能依据结果改进 | 用效率、准确率等指标做量化评估，持续迭代优化 |
| **品格倾向** | 遇到错误就停下 | 能自己排错，主动查找资源 | 能反思过程，并把经验用到后续学习中 |

> 评分时要对照每条标准的**边界说明**，不对“不要求”的内容扣分，例如大 O 分析、形式化证明、从零实现复杂的数据结构。

## 四、要点总结

1. **学习行为**：围绕 CT6–CT9 展开，即“定义问题 → 抽象建模 → 创造实现 → 测试改进”，并贯穿迭代设计、用户反馈、协作和反思。高中阶段特别强调**数据驱动的方法**（机器学习）和**批判性评估 AI 输出**。
2. **评价方法**：标准本身**不规定评价方式**，但它的行为动词、边界说明、实践对应和学习进阶提供了评价框架。标准里写明的检验手段包括测试用例、效率和正确性指标、模型准确率、对照设计规格以及用户反馈。课堂上可以用作品、测试报告、设计文档、读代码讲解、迭代日志和反思作品集来持续评价。
